# Filing adapters: code-grounded matrix and bounded milestones

2026-10-14. Read-only baseline: `concept2cure-v2`, `87b27c897c5d1be20b0527009bcaf425ebbf3af6`. Scope: all requested biotechnology/pharma/biologic, medical-device and diagnostic/IVD clients in the USA, EU/EEA, UK, Japan, Canada and Australia. No application changes, credential/API calls, tests, branches or commits. Regulatory interpretations were coordinated with `/root/regulatory_research`; primary-source details are in [regulatory notes](regulatory.md) and [focused rule-pack requirements](regulatory-rule-packs.md). This plan gives implementation contracts and golden cases, not a claim of accepted/deployed capability or a full legal inventory.

## How to read the matrix

- **Authoring** means reachable governed Authoring/Vault in the launch catalog, plus filing-specific outlines when the installed active rule-pack store supports the precise class. A migration/engine file proves retained implementation; it does not prove the deployed pack is installed, correctly scoped, independently qualified or reachable in the launch UX.
- **Package** distinguishes a PDF/materialized ZIP, structured region-specific output and a regulator-validated dossier. FDA is the only current structure-reporting Module 1 builder, and even FDA gets a conformance classification only for a build with an actual empty gap report.
- **IV** below means independent validation: internal deterministic checks exist, configurable external seams exist, but no real licensed execution/profile/current-schema qualification was established by this read-only task. **IV-not-proven** is used deliberately, rather than saying integration code is entirely absent.
- **Template** concerns official forms or format assets; an eCTD regional envelope is not an eSTAR PDF. **Delivery** distinguishes applicant handoff, wire-level receipt, validation and centre/authority review acceptance. No market below gains an agency-acceptance claim from code existence.

## Independent-validation state: additional code found in this continuation

There is more than the generic HTTP validator registry. [External resolver](../../../server/services/ectd/external-validator/index.ts:25) selects a configurable LORENZ CLI/endpoint wrapper, then an opt-in FDA-criteria subset, then noop. [LORENZ adapter](../../../server/services/ectd/external-validator/lorenz-adapter.ts:4) parses known JSON and tolerant XML contracts; it needs actual licensed engine/profile/tooling qualification. [Compilation import](../../../server/routes/ectd-compile.ts:1670) transactionally retains a JSON report against a tenant/program compilation with actor, report hash and replacement history. It does not establish the report's actual source or bind the imported schema to a separately verified package hash/engine version: [retained import fields](../../../server/routes/ectd-compile.ts:1526).

**Static authority-scope seam:** the resolver may select `fda-criteria` (explicitly only a subset); [assessor](../../../server/services/ectd/assess-dispatch-readiness.ts:766) treats every non-noop validator as configured; [gate](../../../server/services/ectd/external-validator/gate.ts:50) checks configured/ran/error count. A subset can therefore satisfy this gate's “agency-grade required” terminology unless a higher caller constrains it. No runtime reproduction is claimed. Add explicit validator authority/coverage rather than treating any successful wrapper as independent clearance.

## Implementation-ready milestones

Milestones are ordered by dependency and bounded client outcome, not by duration. Each workstream keeps one canonical implementation, exact file ownership, fail-first cases and independent expert review. An operational test receipt is required before claiming qualified delivery; changing source code or a status label is not the receipt.

### F0 — One evidence-backed capability/status contract

**Outcome:** every market offer, AnA answer, assembly/readiness/export view distinguishes content applicability, artifact production, official format currency, independent technical validation and authorized delivery. Fix within existing launch surfaces; do not unlock hidden kits as a side effect.

**Own:** `server/services/regulatory/market-support.ts`; `server/services/pathway-engines/device-assembly/assemble-device-submission.ts`; `server/services/pathway-engines/estar/estar-template-registry.ts`, `estar-versions.ts`, `estar-filing-readiness.ts`; the corresponding `AnaToolExecutor.ts` instruction; `server/services/ectd/external-validator/types.ts`, `gate.ts`, `index.ts`; `assess-dispatch-readiness.ts`. Reuse existing serializers/readiness targets; publish a shared typed contract before client work.

**Contract:** `artifactProduced/producible` (actual format/version/bytes), `applicabilityResolved`, `formatPolicySatisfied` (supported/accepted vs recommended vs unknown, cited source/date), `technicalValidation` (internal/subset/licensed independent/imported; engine/profile/version; coverage; package/report hash; provenance), `releaseEligible` (existing approval/signature/export gate), `channel` (sourced/proven/applicant-only/refused) and `delivery` (not sent/in transit/receipt/technical rejected/centre accepted/unknown). A received message or a parser accepting `findings:[]` cannot mean dossier acceptance.

**Golden cases:** complete nIVD/IVD content + actual pinned 7.0 → old official artifact can be produced, current-format filing readiness remains blocked by present platform policy; missing PreSTAR → no official request artifact; current 7.1 bytes + wrong checksum → refusal; current-looking version with stale/unverified source → declared current-policy disposition, never silently fresh; unknown sterile/software/cyber answers and authored contradictions → missing/undetermined findings; PMA supplement uses correct subset of modules; hypothetical AnA leaves never clear project readiness; FDA subset returns clean → internal/subset pass only, cannot clear independent-required claim; imported clean report for other tenant/program/package hash/profile/version → refusal; licensed report errors/malformed severity → refusal. Model narrative cannot rewrite statuses.

**Existing test anchors:** `server/services/pathway-engines/estar/__tests__/estar-version-currency.test.ts`, `estar-filing-readiness.test.ts`; `server/services/pathway-engines/device-assembly/__tests__/`; `tests/routes/ectd-compile-evalidator-import.test.ts`; `server/services/ectd/external-validator/__tests__/external-validator.test.ts`, `lorenz-adapter.test.ts`; `server/services/regulatory/__tests__/market-support.test.ts`.

## Shared acceptance-fixture format

For each milestone keep a small fixture bundle with: permitted original bytes and hash; organization/project/product/study identity; application/jurisdiction/procedure/lifecycle/effective-date contract; pinned rule-pack/official-template/controlled-vocabulary/schema versions; source locator; expert-reviewed applicability/expected findings; expected artifact paths/manifest/hash; independent reference output/report with engine/profile/coverage; signer/role/access/withdrawal cases; delivery protocol transcript only where actually performed. Regulatory sample artefacts, synthetic negative cases and real agency test receipts have distinct labels.

Golden tests should prove the intended refusal by mutation first: wrong country namespace, wrong application class, wrong template bytes, different assay, missing applicability, unapproved source, wrong package hash, wrong validator coverage, ambiguous receipt. Synthetic fixtures demonstrate detection; they never establish an accepted filing. Preserve historical approved packs/artifacts, install new reference versions through durable migrations and verify restricted-role tenant isolation. Reuse existing tests instead of mirroring internals or rerunning unrelated heavy suites.
