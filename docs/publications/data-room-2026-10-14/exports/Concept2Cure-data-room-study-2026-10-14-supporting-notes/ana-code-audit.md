## What already exists and should be extended

1. **Version-bound source selection.** `server/services/ana/draft-project-sources.ts:25` validates 1–8 selected UUIDs and deduplicates them. `:40` resolves the open project, checks ownership before fetching text, requires matching row/catalog content hashes and usable extraction, and refuses removed or superseded data. `:58` gives the model document identity, content hash, exact character span, completeness and OCR/source availability. `:70` labels source data untrusted, forbids treating excerpt review as whole-document review and preserves original-file withdrawal/OCR caveats. This is substantially safer than an unconstrained prompt containing arbitrary client text.

2. **Whole-text reading is an actual receipt contract.** `server/services/ana/document-catalog-tools.ts:364` supports offset reads, returns extraction confidence and existing comprehension, and defers read receipts until result delivery. `server/services/ana/read-receipts.ts:123` records a receipt only when the handler's result passes the model result budget byte for byte unchanged. Its tests at `server/services/ana/__tests__/read-receipts.test.ts:38` exercise replaced, cancelled and amended results; `:96` proves an oversized read is replaced rather than cut. Catalog coverage is a distinct concept from selected-source excerpt review. Preserve this distinction.

3. **Governed catalog suggestions are real.** `server/services/ana/document-catalog-tools.ts:475` checks Vault write authority, project scope and writes proposer attribution; `:512` returns `catalogState: suggested` and tells the person where to confirm/correct. `:308` carries suggested/confirmed state into re-reads. `server/startup/document-catalog-bootstrap.ts:27` now initializes missing catalog toggles ON while preserving previously disabled rows. Semantic embedding remains optional. Do not state the catalog is universally enabled in deployed tenants without inspecting their actual toggle state.

4. **Keyless document and passage search already exist.** `server/services/vault/vault-assistant-search.ts:46` always searches current project documents with PostgreSQL full text and optionally adds semantic comprehension matches. `server/services/vault/document-chunking.service.ts:215` writes full-text-searchable chunks without an embedding provider, and refuses an oversized document instead of indexing a prefix (`:247`). `server/services/advancedRAGPipeline.ts:1173` falls back to the lexical passage arm without an embedding and `:1276` fuses dense and lexical hits when embeddings exist. It is unnecessary to build another vector database or parallel RAG subsystem to deliver basic source-aware search.

5. **Typed clinical claim comparison already exists.** `server/services/truth-engine/clinical-claims.ts:1` describes a deterministic, non-model comparator. `server/services/truth-engine/clinical-claims/types.ts:190` defines the claim frame: study/pool, population, arm/contrast, measure, scope, analysis, endpoint, scale, unit, CI and adverse-event basis/causality. `types.ts:80` carries source quotes, character offsets and the contextual origin of each slot. The comparator refuses mismatched frames, distinguishes precision as written, and reports unread/unframed/not-compared evidence rather than fabricating consistency. `server/services/truth-engine/__tests__/clinical-claims.test.ts:1` specifies a 431-case adversarial corpus with expected and forbidden outcomes, valid quotes/offsets, and deterministic repeat results. The source comment is evidence of test intent; passing at this head was not re-run here.

6. **Both number presence and same-frame agreement are on the draft creation path.** `server/services/authoring/authoring-from-draft.ts:337` verifies source versions inside the save transaction, computes `checkSectionFigures` and `checkSectionClaims` from the same verified excerpts, and records both checks in document/audit provenance (`:349`). `server/services/authoring/draft-figure-check.ts:76` labels a found/unverified figure with document, content hash and confirmed source offset. `server/services/authoring/section-claims-check.ts:239` compares only section-to-cited-source pairs, reports conflicts, and preserves reasons for non-comparison. The tests at `server/services/authoring/__tests__/section-claims-check.test.ts:33` explicitly detect a draft nausea rate of 12% against a same-frame source rate of 18%, with both source quotes.

7. **The platform also checks a document against itself.** `server/services/authoring/document-figure-consistency.ts:108` builds one source from section headings/text and calls the existing same-frame comparator. `server/routes/authoring.router.ts:4544` loads current authoring sections for this check; a failed read returns unavailable, not an empty consistent verdict. This handles human/imported/edited text in addition to AnA draft creation. Do not recommend rebuilding within-document numerical reconciliation.

8. **Source and machine/human lineage is an existing atomic gate.** `server/services/clinical-regulatory-evidence/lineage-gate.ts:335` records deterministically verified quote spans, separately records model-asserted paraphrases, attributes the remainder to a machine or human, then asks the database whether the spans cover the content before commit. `source-attribution.ts:176` explicitly distinguishes a paraphrase assertion from a verified quotation. `server/services/ana/drafting-source-lineage.ts:60` resolves supplied evidence/artifact IDs through a shared canonical source resolver and names dropped citations. The tools use this gate inside content transactions; `server/services/ana/__tests__/write-section-source-lineage.test.ts:83` and `drafting-source-lineage.pglite.integration.test.ts:95` pin the integration. Preserve quote support, asserted paraphrase, machine drafting, human acceptance and scientific qualification as separate claims.

9. **Statistical run persistence and replay exist, but with narrow coverage.** `server/services/stats/computation-runs.ts:55` stores canonical inputs/outputs, SHA-256 digests, method/engine versions, seed and purpose. `server/services/biostatistics-bridge/bridge-service.ts:418` records a sample-size run, applies the design patch and records the governed action in one transaction; the design and action both name `computationRunId`. `server/routes/biostat-bridge.ts:126` exposes replay. `computation-runs.ts:93` separately reports input integrity, output integrity, reproduction and version match. At `:110`, the replay dispatch handles only `ana-biostats:compute`; it honestly refuses unsupported replay methods. `server/services/stats/__tests__/reproduce-computation-run.test.ts:108` covers edited input/output and moved engine versions. This is a foundation for broader analytical reproducibility, not a universal compute ledger today.

10. **Source-change impact and safe withdrawal already exist.** `server/services/clinical-regulatory-evidence/span-lineage.service.ts:1087` lists citation spans whose recorded checksum differs from source content. `source-usage.service.ts:484` scopes changed usages by the citing project's document. `server/services/document-data-disposition/derived-impact.ts:47` walks recorded captured/upload ancestry across same-tenant project boundaries, keeps malformed named dependencies visible as unverified and fingerprints the dependency snapshot. `impact.ts:174` adds derived workbook and filed rendition dependencies to disposition blockers. Tests at `derived-impact.pglite.integration.test.ts:164` prove stale preview rejection, and `:186` covers a recorded grandchild. These tests use PGlite, not separate live PostgreSQL connections, live RLS or audit-HMAC qualification, as their header states.

11. **AnA action governance is mature enough to reuse.** `server/services/ana/AnaToolExecutor.ts:482` checks launch scope, makes subagents read-only, restricts model-authored governed writes to approved models, refuses a person's exclusive acts and proposes changes requiring human confirmation. `:549` checks the confirmed writer's organization role; `:565` also enforces named program/record tenant scope. `server/services/ana/__tests__/ana-cannot-sign.test.ts:66` pins electronic-signature handoffs, including confirmed attempts. A draft's recorded `governedWrite` allowed/refused/unverified status is distinct from merely allowing storage as a working draft: see `authoring-from-draft.ts:111`. AnA must never become a replacement for accountable signer/reviewer acts.

## What remains incomplete at the current head

### 1. Selected-source drafting still truncates by position, even though relevant-passage retrieval exists

`server/services/ana/draft-project-sources.ts:49` reserves 48,000 characters total; `:56` reads the first 12,000 characters of each selected document. Up to eight IDs may be selected, but five long sources exhaust the total and fail closed rather than silently disappearing (`__tests__/draft-project-sources.test.ts:68`). This does not expose endpoint tables late in a long CSR.

The cap is encoded in the saved-receipt contract too: `server/services/authoring/draft-source-references.ts:19` requires `span.start === 0` and `span.end <= 12000`; `:69` re-verifies the prefix. Changing the source loader alone is insufficient. Extend this canonical contract to version-bound nonzero/multiple passage ranges, preserve table title/row/column/footnote context, return extraction/coverage caveats, and re-verify exact ranges at save and new rendition/export. Reuse lexical/hybrid retrieval plus delivered-read receipts. Benchmark a long CSR where the answer lives beyond character 12,000 and a table needs its footnote to interpret the denominator.

### 2. Catalog key-data checks bind values to the document, not properties to their proper context

`server/services/ana/document-catalog-tool-defs.ts:109` explicitly permits keys of AnA's choosing that are not checked, with exact-transcribed string/number values. The parent agent independently demonstrated that a source with Assay A sensitivity 95.0% and Assay B sensitivity 99.2% accepts `{ assayA_sensitivity: '99.2%' }` under the current presence check. This remains a suggestion awaiting human confirmation; it is not a governance bypass. It is an evidence-context gap.

Upgrade the existing record with typed fact items: measure/property, subject (study/assay/device/product), value-as-written, unit, denominator/population, specimen/matrix, method, threshold/timepoint, source version and exact quote/locator, validation status and human decision. The existing clinical frame/compare engine demonstrates the pattern, but does not currently define full diagnostic assay or device performance measures. Preserve the legacy record during migration; replace its unchecked-context semantics rather than adding a duplicate catalog.

### 3. Typed comparison coverage is strongest in pharma clinical claims

`clinical-claims/types.ts:170` enumerates measures such as N, incidence, responder, effect, exposure and demographic. Its roles (`:11`) are CSR/Module 2/ISS/ISE/USPI/SmPC/other, not a device/IVD evidence taxonomy. A search of these modules finds sensitivity as analysis role, not diagnostic sensitivity/specificity measure semantics. Yet deterministic IVD analytics already exist in `server/services/stats/analytical-performance.ts:1` and extensions: EP05 imprecision, EP17 detection capability, EP06 linearity, method comparison and ROC calculations. Extend the current typed fact/claim vocabulary for diagnostic sensitivity/specificity (reference standard, specimen, threshold, prevalence/population, confidence interval), LoD/LoQ (analyte/matrix/unit/protocol), precision (run/day/site/lot/operator), and device bench endpoints (test method, configuration, acceptance criterion), each with domain expert corpora. Do not claim existing drug clinical tests validate those new domains.

### 4. Computed/derived character lineage is not equivalent to stored run or draft-check provenance

`shared/schema/document-span-lineage.ts:43` permits usage `derived`/`computed`, but provenance kinds at `:54` point to a CRE source or human/machine assertion; there is no first-class computation-run reference. Searches at this head found derived usage creation in tests/carry-forward handling, not a general production writer linking a statistical result span to `stats_computation_runs`. Draft numeric findings are persisted as document provenance, not derived span-lineage rows. Improve the existing lineage schema/contract to reference a computation run and exact output field/result hash; record deterministic derivations with inputs, transformation/version and source locators. Expand replay method dispatch and store figures actually used. Avoid describing every calculation as persistently reproducible today.

### 5. Cross-document checks are not yet a living governed evidence ledger

The selected-source claim check is called at draft creation (`authoring-from-draft.ts:337`), over selected excerpts. The within-document check handles current authoring sections separately. Existing staleness and withdrawal gates detect changed dependencies; they do not automatically prove that current cross-document scientific claims still agree after arbitrary author edits or a new evidence cut.

Extend the existing services with dependency-triggered rechecks of impacted claims/sections, a saved evaluation receipt bound to input/output hashes, a reviewed resolution and a task/hold when needed. AnA may explain and propose a patch, while the deterministic comparator identifies what changed and a human decides. Make the first use case a data-cut update that changes one endpoint and maps exactly which summary/label/response passages require review; include false-positive controls for different populations, arms, thresholds and timepoints.

## Recommended implementation order

1. Typed catalog fact records and contextual checks, with two-assay/two-study adversarial fixtures.
2. Relevant passage receipts across source loading, drafting, save and export; retain exact version/range verification.
3. Broaden reproducible method registry and connect used numeric spans to run/output provenance.
4. Domain-specific device/diagnostic fact frames and expert-designed corpora; reuse existing IVD computations.
5. Incremental impacted-claim rechecks and governed resolution history across sources, drafts and filing versions.

All are extensions to the existing catalog, Authoring, Vault, governed AnA tools and source lineage. Roadmap items requiring new product/filing scopes should be identified as such under CLAUDE.md Rule 2 and the user's founder direction; do not quietly broaden submission claims.
