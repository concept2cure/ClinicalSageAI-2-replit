Direct canonical publication to concept2cure-v2; local/Codespaces qualification only, no deployment or agency/provider calls.

Extend these owners; never maintain a second filing registry. Segment alone misses vaccine EUA and combination-product RFD, whose current device-oriented scaffolds cannot substantiate therapeutic coverage.
- `server/services/market-specs/document-template-library.ts` owns component outlines and projects filing blueprints. `lifecycle-record-outlines.ts` and `ind/ctd/lifecycle-document-types.ts` own detailed amendments, meetings, clinical-hold responses, ISS/ISE and lifecycle parts. Several detailed records have no exact editor start despite generic filing starts existing.
- `server/services/regulatory/templateCatalog.ts` owns offered metadata and per-filing template sets. It omits exact protocol, IB, SAP, ICF, DSUR and PBRER metadata. `authoring/builtin-authoring-templates.ts` therefore classifies their real outlines as preparation/manual; saved-section drafting refuses them. Complete exact metadata and preserve section-specific original-record limits. Whole filings remain packages, not universally narrative documents.
- Further source inspection: `ctd-component-outlines.ts` drops the existing CTD guidance contentType distinction while drug_substance/drug_product metadata disables all narrative. The canonical record identifies narrative parts (including3.2.S.1,3.2.S.4.5,3.2.P.2,3.2.P.5.6); tables/mixed originals remain source preparation. `labeling/labeling-intelligence-knowledge.ts` owns USPLR highlights/full prescribing sections but no exact USPI editor component exists; its separate PI store is organization-wide, not verified project/product lineage. `authoring/nonclinical-study-report-structure.ts` owns seven working-report parts already used by IND M4; expose those records, retaining original GLP/signature/source-tabulation protections. These are working documents, not validated manufacturing output, SPL delivery or replacements for signed reports.
- `server/services/authoring/ind-authoring-templates.ts` selects deliverable structure from placement codes; early protocol-outline resolves a broad M5 study-report tree including CSR headings, while finalized protocol resolves the correct protocol structure. Its SAP deliverable has one heading although a complete SAP component exists. Fix selection through existing records, not another protocol/SAP outline.
- `client/src/concept2cure/v2/surfaces/ProjectPlan.tsx` offers full plans only for initial US IND/device projects; other biotech filings explicitly have no plan. `AuthoringCreateExport.tsx`/`AuthoringTemplatePicker.tsx` expose a global roster and start blank, without filing-guided choices. - `DocumentWorkbench`, source assembly, SourceImportDialog, current source/target admission, authoring-source-import, saved references, tracked AnA remedies, peer review, signature and export services already own the document lifecycle. Reuse their source hashes, provenance, permissions and version guards. - `ProjectRespond.tsx`, `AgencyResponses.tsx`, agency-responses routes and `response-service.ts:saveResponseTx` own authority questions, answer revisions, visibility, signatures and packages. Answers still use a separate textarea. A same-editor bridge must use existing workflow-copy import and explicit governed writeback through saveResponseTx, with current letter visibility, source and saved-editor version checks. - `registryCoverage.ts`/`scripts/regulatory-coverage-report.ts` already measure blueprint/form/channel backing; their production_ready label is not runtime authoring or release qualification. Extend that report with actual editor template facts and explicit evidence gaps.
- `server/utils/logger.ts` sends Pino diagnostics to stdout by default. Complete the existing logger's explicit CLI stderr destination and initialize report imports only after selecting it.
