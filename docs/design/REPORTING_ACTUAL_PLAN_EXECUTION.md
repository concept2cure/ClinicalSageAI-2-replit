# Reporting execution uses the actual plan

W1 / D2, Reporting & analytics, `concept2cure-v2`, 2026-10-14. Approved bounded client repair; publication and whole-tree gates belong to the control tower. Implementation evidence will be filed separately. The regional applicability phase's sixteen source pins were verified unchanged before this work.

A known Free plan is resolved and denies report generation. The existing client rank treats any tier outside its three preview controls as Standard, so a writing Free client can be offered a base report that the server refuses. Selecting a Standard/Enterprise preview also currently affects the decision used to request a run. The client must distinguish browsing another plan's types from executing under the organization's recorded plan.

## Contract

- Preserve the three existing Standard/Professional/Enterprise preview choices, existing styles, known-plan comparisons and read-only catalog/pack behavior. Free ranks below Standard; no new plan selector, price, model, module, capability or dependency is added.
- Keep `canWrite` as the editor-role decision. Keep explicit `tierResolved:false` refusal and its verification copy first. Preserve the currently declared omitted-flag compatibility for legacy rows; canonical server projections now supply the explicit boolean.
- Preview may reveal report types and their requirements. Generation availability and the last client decision before any run POST use the actual recorded plan and any explicit canonical per-type denial. A selected preview cannot grant execution.
- A known-plan refusal says which existing plan is required. It must not say the plan could not be verified or that a writing user lacks an editor role. The minimal optional catalog reason prop may supply that explanation to disabled existing controls, including a document-bound run; no parallel catalog renderer is introduced.
- Canonical source applicability remains independent and precedes a plan explanation. A wrong market/kind, missing filing context, unavailable context, unsupported scope, disabled/unregistered type or genuinely uncomputed engine keeps its existing reason/state/code. Preview and plan changes cannot repair a filing or make such a type runnable. Preserve the regional projection and its Availability filter.
- Saved-run/history/library navigation and retained report reads remain available. Preserve the exact bundle PDF response/session-revision guards and pending export behavior. Existing server access, plan, scope, audit and signature gates remain authoritative.

## Bounded ownership

The UI owner changes `Insights.tsx`, only a minimal unavailable-reason prop in `InsightsCatalogPanel.tsx` if necessary, and focused client tests. Regional backend and other production files remain frozen. No schema, provider, native database, compiler, index, commit or push operation belongs to this slice.

## Verification

Before production mutation, exercise actual user interactions against the current source and preserve failing cases:

- Writing user, canonical resolved Free, explicit base-report entitlement false: Find/Enter, pack and catalog send no run POST and show the known plan requirement.
- Free previews Standard and Enterprise: catalog/pack stay readable while requests remain refused under Free; the real plan is unchanged and no role/verification error substitutes for entitlement.
- Document-bound catalog action stays disabled for a known plan refusal with its precise reason.
- Known Standard/Professional/Enterprise base reports remain executable; an explicit canonical per-type denial remains denied even if local family rank would allow it.
- A lower known plan previewing a higher one cannot grant a disallowed report. Existing plan preview controls remain browseable.
- Explicit unresolved plan keeps verification-denial precedence, legacy omitted flags retain their declared behavior, and retained history still opens with no generation POST.
- Wrong-filing/context and unsupported scope controls keep their exact reason/state/code under Free and previews.

Run all existing Insights component regressions and scoped lint, preserve earlier regional/UI/PDF/browser evidence unchanged, and file new red/green/source-pin artifacts with phase qualifications. These client tests do not establish native server policy, scientific or clinical validity, dossier completeness, agency readiness or deployment. Root owns final compilation and publication.
