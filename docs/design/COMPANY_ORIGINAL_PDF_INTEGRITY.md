# Registered legal and signed originals in eCTD packages

This closes the original-byte integrity gap identified in the company-document workflow completion contract. It extends the existing Vault materializer, core adapter and regional packager; no new storage pipeline, approval mechanism or production dependency is introduced.

After admitting the Vault source row, the materializer reads matching active and archived records from the canonical tenant-keyed `company_legal_registry` through `readCompanyLegalRegistryForVault`; there is no settings-array fallback. `LeafSourceIntegrity` carries the source SHA-256, Vault version identity and matching immutable registry references through `ResolvedFile` and `EctdLeaf`. Archived registrations retain original-byte protection: inventory retirement does not authorize rewriting their files. Unknown or inconsistent source/registry metadata refuses packaging. Existing current approval, content hash, applicability, date, tenant and program checks remain independent.

At the final packaging boundary, the source digest is checked again. Parsed PDF objects, including compressed objects and indirect references, are inspected for embedded signatures. A registered legal original or structurally signed PDF is never sent to Ghostscript. Ordinary unsigned PDFs retain the existing normalization behavior. Invalid or ambiguous signature structures refuse with an actionable error. Supported signature ByteRange has four nonnegative integers and excludes the actual Contents token; uncommon or malformed layouts require review. Detection establishes structure only, not signer identity, cryptographic validity, certificate trust or agency acceptance.

Preserved originals are inspected by veraPDF using their unchanged bytes. Only an explicit compliant PDF/A-1b validation report establishes compliance; a missing validator, failed validation, wrong profile, ambiguous report or changed validation input remains unverified. The deployment's mandatory PDF/A policy refuses such an original instead of converting it. The existing organization policy at transmission also refuses unverified originals and receives the validation reason. Preservation itself grants no PDF/A exemption. The existing treatment of recognized official FDA forms remains separate.

The optional `OriginalPdfProof` on each preserved leaf records source and shipped SHA-256, immutable legal references, preservation reasons, structural signature presence and the original-byte PDF/A verdict. It explicitly records `cryptographicSignatureValidation: not-performed`. The proof travels through the persisted sequence manifest and package governance manifest; it does not modify the agency's eCTD backbone or replace its MD5 requirement. Before the ZIP is written, the actual compressed archive is reopened and each preserved entry is hashed against both proof digests. Missing, replaced or overwritten originals refuse packaging.

Verification includes the real canonical registry → Vault → materializer → core adapter → final ZIP flow with a conversion toolchain stub that changes ordinary PDFs. Extracted original bytes, registry references and source/shipped hashes must match. Removing the adapter's source-integrity propagation makes that regression fail. Additional coverage exercises compressed signatures, malformed structures, source drift, overwritten/missing final entries, mandatory PDF/A refusal and positive original validation. Legacy packaging fixtures now use actual deterministic PDFs so signature inspection is exercised rather than bypassed.
