# Reviewed company stationery variants

This completes the named-presentation portion of [the authorized company-document workflow](COMPANY_DOCUMENT_GAP_CLOSURE.md). Company settings remain the organization default. Publishing a named design never changes those settings or their revision, and no export selects a variant automatically.

`POST /api/client-branding/company-documents/designs` stages the current unsaved company presentation with a name, optional project/market/language/subsidiary scope, the current default profile revision and a reason. The letterhead goes through existing raster validation and canonical template normalization and is stored only in `c2c_template_specs`. The tenant-keyed design record holds its identity fields, immutable scope, template pointer and deterministic hash. It contains no legal registry or duplicated template specification.

`GET /designs` lists accessible designs with UUID cursor pagination. An optional `state=published&sequenceId=<id>` derives the admitted filing's project and market on the server. A language or subsidiary restriction is unresolved when that filing supplies no such recorded fact; those designs are excluded from the filing picker. `GET /designs/:id` returns the candidate, changed presentation fields and server-derived review/publication permissions and blockers. Private-project access applies to lists, candidates, proofs and selection.

`POST /designs/:id/review` requires a different current brand manager and the exact staged hash. `POST /designs/:id/publish` requires that independent review, the same hash, a reason and a fresh organization-default revision. Both recheck the canonical template under a share lock. Template drift requires a new staged design. Each published variant retains its own immutable presentation revision under its variant ID; later template edits cannot change it. These are presentation reviews, not cryptographic signatures or attestations of regulatory acceptance.

All three mutations acquire the organization row lock before writing. Template creation, design metadata, retained presentation and chained audit rows share the request's transaction. Missing membership, permission, stale revision, changed hash or lost audit rolls the operation back. Database guards prevent candidate editing, self-review, invalid state transitions, ordinary deletion and truncation. Eligible tenant disposal uses the existing platform/pending-deletion/no-active-hold boundary.

`POST /designs/:id/proof` accepts the expected design hash and uses the canonical DOCX renderer. Its actual output carries the retained identity and styling, a draft or published-proof label and a statement limiting the proof to stationery. Access and hash/state are rechecked before audited delivery. The existing unsaved `/letterhead/preview` remains available before staging.

Server workflows resolve an explicitly selected ID with `readPublishedCompanyVariant(q, organizationId, id, admittedContext)`. The helper verifies current membership, project access, each restricted scope, the retained revision and its hashes, returning the historical presentation with `variantId`. Unknown or mismatched target facts refuse. An explicit export selection applies that presentation only to that output, independently of automatic-default preferences; callers retain the original snapshot and record `explicitSelection`, variant ID, revision and presentation hash in export provenance.

Verification includes real PGlite state/transaction/retention tests, creator-review and source-drift refusals, no default mutation, tenant/project and filing-scope isolation, pagination, and actual Word XML and audited-delivery refusal checks.

An owner or administrator may optionally require independent review for the organization default. The policy defaults off. Enabling it refuses until the current default exactly matches an explicitly activated, independently reviewed and published organization-wide design. A project, market, language or subsidiary restriction prevents promotion to the unrestricted default. Normal publication continues to leave the organization default unchanged.

`POST /designs/:id/activate-default` accepts `{expectedRevision,expectedHash,reason,applyToReports,applyToSubmissionCorrespondence}`. This separate action replaces the saved default presentation using the published retained proof and records its server-controlled approval reference through the canonical profile writer. It preserves legal inventory, legal policies and the independent-review setting. The transaction rechecks the published proof and records the source design, review hash, retained revision, resulting default revision and automatic-use preferences. A missing mandatory audit refuses activation.

The canonical profile writer verifies every write while the review policy is enabled, including ordinary saves, legacy adoption and restoration. It resolves the trusted published design and compares normalized company identity, logo and letterhead at a fixed revision; user-supplied approval claims are never accepted. Legal-library changes and automatic-use preference toggles do not change the approved presentation. An unreviewed presentation must be staged, independently reviewed, published and explicitly activated before it can replace a protected default. Policy enable/disable is a separate owner/administrator change at `PUT /branding-policy`, with the current default revision and an audit reason.
