# Company letterhead on governed report exports

This extends the company-document profile described in [COMPANY_DOCUMENTS.md](COMPANY_DOCUMENTS.md) into Reporting & analytics. It uses the existing canonical PDFKit `Writer` and its embedded multilingual fonts, rather than introducing a document generator.

`applyToReports` is off by default. When enabled, the authenticated organization's saved company profile is read using the export's tenant transaction and supplied as an optional presentation input to individual run PDFs, bundle manifest PDFs and complete retained report packs. The report document and seal are never edited. The export audit records `companyBranding.applied`, and, when applied, its revision, profile SHA-256 and renderer identifier `company-letterhead-report-pdf-v1`, separately from the exact PDF hash and source seal hashes.

Supported presentation includes company name, address, contact and registration details; header text and alignment; confidentiality notice; raster logo; accent rule; footer text and custom company page numbers; Letter, A4 and Legal page sizes in either orientation; and margins. Logos retain their aspect ratio inside an 84 × 44 point header area. Header logos repeat on each page; a cover logo appears only on the first page. An animated GIF is rendered as a static first frame through the existing native canvas. PNG/JPEG/GIF bytes use the company asset validator and never become a URL, HTML, SVG or file path. Limits are 2 MiB, 4096 pixels per side and 16 megapixels.

The PDF renderer deliberately retains its canonical report body typography, table/chart rendering, embedded fonts, signature manifestation, seal verification, draft/unverified watermarks and mandatory run/bundle/export/page labels. Template body fonts, named styles, form fields and table style properties do not alter these governed reports. The company footer's page-number toggle controls only company page numbers; the export's mandatory page labels always remain. Charts adapt to the available content width. Word correspondence continues to use the canonical DOCX renderer and its broader TemplateSpec support.

Header and footer content reserves space on every page. Reporting accepts margins from 0.25 to 4 inches, at least 200 points of content width, and at least 180 points of content height after letterhead and mandatory labels. Invalid images, unsupported glyphs or a design that leaves too little room refuse the export with an actionable error, rather than hiding content or silently dropping enabled letterhead. An unset/disabled company profile preserves the existing PDF bytes for the same export identity.

Legal library documents remain separate unchanged originals. Branding a report neither attaches those files nor attests that a legal document meets a particular agency's requirements.

Verification covers actual extracted PDF identity on overflow pages, embedded image objects, actual landscape/A4 geometry, disabled-profile byte equality, original sealed content and signature preservation, draft/page identity, all three export routes, tenant-bound profile reads, audited revision/hash and refusal before export when configuration is unavailable or unsafe.

## Word letterhead fidelity

The existing DOCX factory accepts optional physical page geometry, running-header alignment, organization name, accent rule and company page-number format through the TemplateSpec adapter. Word page fields implement `{PAGE}` and `{PAGES}`. PNG/JPEG/GIF media bytes are embedded as supplied. Header-logo visibility and the company page-number toggle are respected. Company correspondence uses `includeCover: false` so the draft starts on the letterhead, with confidentiality in the footer, rather than adding the factory's regulatory cover. Existing factory callers keep their cover unless they explicitly opt out. Actual OOXML tests verify Letter/A4/Legal size and orientation, margins, header text/alignment/color, original image bytes, footer fields and the original default behavior.
