## What already exists

- `client/src/concept2cure/v2/surfaces/Insights.tsx` is the existing reporting canvas. It creates and opens saved runs, renders reports, finalizes through the shared signature dialog and exports PDFs. Its context key tracks program, organization, scope and segment, but not the authenticated account or session revision.
- `InsightsCatalogPanel.tsx`, `InsightsRunsPanel.tsx`, `InsightsSchedulesPanel.tsx`, `InsightsBundlesPanel.tsx` and `InsightsRunEvidence.tsx` already provide discovery, history, scheduling, packs, dependencies and seal facts. Their existing reads do not independently refresh when an account changes without a URL change. `insightsLibraryModel.ts` already guards bundle PDF downloads; the single-report export lacks the equivalent checks.
- `client/src/services/portal/authService.tsx` owns session revision, current account and auth events. `editor/authoringCurrentRead.ts` already exposes `captureAuthoringSession` and `useAuthoringReadSession`, which combine its canonical revision guard with the actual account object while allowing ordinary bearer refresh. Reuse this existing ownership primitive instead of adding another session mechanism or fetch transport.
- `server/services/report-os/scheduling/generate-deliver.ts` computes through the canonical dispatcher and atomically persists the run, notifications, audit and occurrence cursor. Its existing late creator/recipient checker is skipped unless optional source-project evidence is nonempty or the report is a lifecycle calendar.
- `server/routes/report-os.ts` has the same current-actor/source callback inside `createRunOnChain`, but installs it only for lifecycle calendars. Other manual runs can persist after authority changes during computation.
- `server/services/report-os/project-access.ts` already evaluates exact scopes, all recorded source projects and malformed present source evidence. `c2c/current-program-access.ts` reads active current actors; `forShare` retains the evaluated organization/user/membership rows. `report-os/persistence.ts` rolls back run, snapshot, dependencies, chained audit and enlisted effects together.
- `server/services/report-os/scope-ownership.ts` already verifies an active client workspace, nonarchived scope, linked-record parent and program-group membership. Reuse `resolveOwnedReportScope` on the supplied late-check executor, without a cached `verifiedProject` shortcut, so fresh output does not rely on a scope archived or moved to another workspace during computation. The canonical dispatcher already records the actual source project IDs for program-group computations; retain those recorded inputs rather than substituting the group's later membership.
- Existing reporting engines, regional applicability, plans, report lifecycle and the newly synchronized company/legal package workflow remain the implementations to use. Relevant path-limited deleted-history searches found no deleted predecessor to restore.

## Completion contract

1. Bind the existing canvas subtree to the actual canonical account/session owner. On an observed owner change, withdraw overview, report, catalog, history, schedules, bundle selections, evidence and signing state together. Refetch for the current owner using the existing transport. Program changes retain their current context behavior. Ordinary bearer refresh keeps the same owner.
2. Old asynchronous responses and old handlers may not render, download, finalize or submit a run under replacement credentials. Check ownership before dispatch and after asynchronous response/body stages. Apply this to saved/deep-linked runs, generated runs, signature callbacks and single-report PDF export. Preserve existing bundle guards.
3. A sent write may already have completed. Withdrawing its private result must not assert rollback, imply nothing happened or retry automatically. Use generic recovery wording and the existing Run history. An unclassified transport/server failure or malformed positive run response has an unconfirmed outcome; an explicit `REPORT_RUN_NOT_RECORDED` or typed current-access refusal retains its precise known refusal. Export remains a read; finalization remains the explicit shared signature ceremony.
4. Every scheduled report must re-evaluate current scope/workspace ownership, the creator's writing role and every recipient's exact source access after computation and on the enlisted persistence client before delivery effects. Optional or absent source-project evidence must not switch this protection off. Malformed present evidence refuses.
5. Every manual report must install its existing current-actor/source check and the current owned-scope check on the enlisted persistence transaction. Typed access refusals remain typed. The callback must not obtain another pool connection or construct a new request/actor. Scheduled preflight reads keep their existing worker pool; enlisted checks use only the supplied client.
6. Actor locks and observed late project-policy checks must be described accurately. This increment does not claim serialization against every independent project-sharing writer. It adds no engine, prediction, jurisdiction, agency qualification, app, dependency, permission grant or model approval.
