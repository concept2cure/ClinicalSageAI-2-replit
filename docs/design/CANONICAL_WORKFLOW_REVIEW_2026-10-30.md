## Same-mounted project and session isolation

### What already exists

`ProjectHome.tsx` supports same-mounted project selection changes and already uses `useShellProject`, `useAuthUser` and `editor/authoringCurrentRead.ts`'s `useAuthoringReadSession` for its owned program read. No second workspace, hook engine, API, storage or authority is needed.

Candidate boundary: keep `ProjectHome` as the public owner wrapper, capture its existing project and authoring-session context once, and key the single existing workspace implementation by selected-project identity, actor and session key. Pass those captured values into the inner implementation rather than duplicating reads/session hooks. Exclude stage/title from the key, preserve the recorded step and every existing data/shape/access guard, and preserve ordinary-refresh drafts. Different project/actor/session starts fresh; within-project stage changes and ordinary refresh retain the exact textarea, draft, history and read count.
