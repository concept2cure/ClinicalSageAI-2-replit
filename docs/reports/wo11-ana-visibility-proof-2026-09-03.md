## 2. The `toTurn` mapping — before and after

**Before** (`ConversationThread.tsx:26-50` at `499f096`):

```ts
function toTurn(m: AnaChatMessage): CtTurn {
  if (m.role === 'user') return { role: 'user', text: m.text };
  const grounding = (m.groundingSources || []).map((s) => ({ src: s, ok: true }));
  return {
    role: 'ana',
    answer: m.text || undefined,
    thinking: m.thinking || undefined,
    grounding: grounding.length ? grounding : undefined,
    executedActions: m.executedActions?.length ? m.executedActions : undefined,
    pendingSignoffs: m.pendingSignoffs?.length ? m.pendingSignoffs : undefined,
  };
}
```

Dropped: `statusPhase`, `toolCalls` (with rounds and status), `detectedLens`,
`detectedDocumentType`, `generatedDraft.title`, `streaming`.

**After** (`ConversationThread.tsx:33-92`):

```ts
function toTurn(m: AnaChatMessage): CtTurn {
  if (m.role === 'user') return { role: 'user', text: m.text };
  const grounding = (m.groundingSources || []).map((s) => ({ src: s, ok: true }));
  const activity: AnaActivityProps = {          // the SAME mapping V2App.adaptChatMessage uses
    streaming: m.streaming,
    phase: m.statusPhase,
    lens: m.detectedLens,
    documentType: m.detectedDocumentType,
    toolCalls: m.toolCalls,
    thinking: m.thinking,
    draftTitle: m.generatedDraft?.title,
  };
  return {
    role: 'ana',
    answer: m.text || undefined,
    grounding: grounding.length ? grounding : undefined,
    activity: m.streaming || hasReportableWork(activity) ? activity : undefined,
    executedActions: m.executedActions?.length ? m.executedActions : undefined,
    pendingSignoffs: m.pendingSignoffs?.length ? m.pendingSignoffs : undefined,
  };
}

function hasReportableWork(a: AnaActivityProps): boolean {   // V2App.tsx:212's condition, on the mapped shape
  return Boolean((a.toolCalls && a.toolCalls.length > 0) || a.lens || a.documentType || a.thinking || a.draftTitle);
}
```

`activity` is present while the turn is in flight (the phase line is the waiting state) and, once
settled, only when there is real work to show. A settled turn that ran nothing carries no record.
`hasReportableWork` is inlined with a comment pointing at `V2App.tsx` rather than imported, because
`V2App` is the shell root and this surface is one of its lazy chunks.

`AnaTurn` renders `<AnaActivity {...turn.activity} />` **above** `turn.answer`, as WO-11 A2 asks
and as the component's own docblock puts it ("the progress before the words"). Note: the WO's
claim that this matches the rail is not accurate — `Shell.tsx` draws the body (`:924`) before the
activity (`:969`). The ordering here follows the WO and the docblock, not the rail.

The two `@media` steps also carry `.ct-composer`, `.ct-comp-atts` and `.ct-comp-foot`, and sit
after those base rules (an `@media` override must follow what it overrides), so the reply box stays
aligned with the transcript at 1600px and 1920px instead of sitting 92px and 172px narrower.

Collapse (Fix C items 1–3): a labelled toggle in the thread header (`Hide side panel` /
`Show side panel`, `aria-expanded`, `aria-controls` → the column's `id` while it is rendered),

`WORK_DOCK_KEY` (`c2c-v2-ana-work-dock`) in `Shell.tsx:514-633` — read once on mount so it survives

column's own close button unmounts with it, a hide moves focus to the header toggle (never on
mount, so a remembered `hidden` does not steal focus on load). The toggle's text colour is

## 7. Deviations from the letter of WO-11, disclosed

- **A3 — the trailing dots were deleted, not replaced.** The WO says to replace them with an
  in-flight `<AnaActivity/>`. Because the in-flight message is already the last turn in
  `anaChat.messages` and A2 renders its activity there, a second `<AnaActivity/>` after the turns
  would render the same record twice ("Do not render both"). The dots survive only as the guarded
  fallback inside `AnaTurn`, for the state the WO names.
- **The `.ct-think` disclosure was removed** (not named in the WO). Applying A1's "same mapping"
  includes `thinking`, and `AnaActivity` renders it; leaving the disclosure would have shown the
  reasoning twice, against ground rule 5. `CtTurn.thinking` went with it.
- **A follow-the-work scroll effect was added** (`ConversationThread.tsx:761-782`). The existing
  effect scrolls only when the turn count or `busy` changes, so the tool rows landing on the last
  turn would grow below the fold. It keys on the in-flight turn's progress and only scrolls when the
  reader was at the bottom before the content grew — recorded by the scroll handler on the reader's
  own scroll, not measured after the DOM has moved the bottom. Without it rows 1–2 could be true
  and invisible.
- **The collapsed stub was removed and the toggle moved to the header.** Fix C item 3 asks for
  genuinely full width; the stub was the only way back, so it had to go together with a visible
  labelled control.
- **The dock cap is 60%**, chosen as "modest"; the WO does not name a number. It is driven by
  `data-artifacts` on `.ct-side`, set from the conversation's real drafts.
- **Fix A, B and C landed together.** The handoff's session-log row and §7 name "WO-11, Fix A"
  under "one fix per session"; the WO bundles all three under one commit message and one
  seven-row table, and the handoff cites that table as the acceptance. If JM wants B and C held,
  they are the two CSS hunks (Fix C steps after `.ct-comp-foot`; the `.ct-side` split) plus the
  header toggle, the persisted state and the stub removal.
- **`hasReportableWork` is inlined on the mapped shape** (`AnaActivityProps`) rather than on the
  message, with the pointer comment the WO allows, because `V2App` is the shell root.
- **`c2c-v2-ct-side-dock` is a new key**, not a new convention: prefix, kebab-case and
  `'shown' | 'hidden'` follow `WORK_DOCK_KEY` exactly.
- **`surface-text-ramp.css` was regenerated** by the repo's script (the drift gate requires it);
  **`AnaWorkPanel.tsx`'s docblock** was corrected; **`docs/handoff/*.md`** were added as the
  handoff's own first line instructs.
- **Assertions were added to an existing suite** (§5). The WO forbids new suites unless a change
  breaks one; it does not forbid making the fix falsifiable, which CLAUDE.md requires.
