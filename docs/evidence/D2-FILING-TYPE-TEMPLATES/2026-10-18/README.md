# D2 · The filing picked is the outline built — 2026-10-18

**Row moved:** D2 (launch catalog: Projects → Authoring → Vault). **Workstream:** W1.
**Scope rule kept:** no new surface, module, tool or model. The 19 outlines added to the
governed store already existed in the platform. Each one is minted from the outline
`getRegistryDocumentTemplate` already served to AnA and the Authoring template picker (the CSR
from the platform's ICH E3 tree). The wizard, the scaffold and the market verdict now read them.

## What was wrong

The New project wizard knew application types only. Twenty-four biotech filings in the catalog
are a *document*, not an application, and every one of them fell to an application type
(`routing-before.txt`; columns: catalog id | registry family | pathwayKey | program type sent |
doc_type | offer tier | pack scaffolded):

| Filing(s) | Was created as | Outline scaffolded |
|---|---|---|
| Prior Approval Supplement, CBE-30/CBE-0, NDA/BLA annual report, REMS, PADER, IND amendment, IND safety report, IND annual report, Type A/B/C meeting, orphan request, BTD / Fast Track / RMAT request, PSP (17) | `nda` (an sBLA: `bla`) | the 73-node NDA (or BLA) dossier, plus an NDA submission spine |
| Clinical study report | `ind` | refused "Not supported" (ICH has no region) |
| Protocol, IB, SAP, ICF, DSUR (ICH), PSUR (EMA) | `nda` | refused |

The five packs that did exist for these filings (`csr:ich`, `ib:ich`, `protocol:ich`, `briefing:fda`,
`psur:ema`) were unreachable from any filing. `csr:ich` held 8 of ICH E3's 16 headings.

## What is now true

- `shared/regulatory/filing-document-classes.ts`: one table of 19 classes over the 24 filings.
  For each class, program type = `c2c_documents.doc_type` = its pack's doc_type, the same pattern
  as `dmf`. The wizard (`Projects.tsx programTypeFor`), the create endpoint
  (`VALID_PROGRAM_TYPES`), the document class (`PROGRAM_TO_DOC_TYPE`) and the workstream bucket
  all read this table.
- `migrations/20261018_filing_class_rule_packs.sql` contains 19 packs and 374 nodes:
  - It is generated by `scripts/db/emit-filing-class-packs.ts` from
    `server/services/c2c/filing-class-packs.ts`.
  - `csr`, `ib`, `protocol`, `briefing` and `psur` get a new version. The other 14 classes get
    their first pack.
  - The CSR is ICH E3 to the depth E3 numbers it: 16 headings, 119 nodes.
  - Each pack states its source basis, confidence, governing rule and uncertainties. None is
    marked reviewed.
- `document-template-library.ts`: the library's own rule ("existing component records win over
  older project heading copies") used to apply only to the annual report. It now also covers:
  - **PAS and sBLA:** the old copy was 16 required generic CTD headings. It is now the `nda_pas`
    record — cover letter, 356h, the change, EA claim and fee — plus the Module 3 sections the
    change updates.
  - **CBE:** the old copy had 5 headings. It is now the CBE-30 and CBE-0 records: shared parts
    are required, each variant's own parts are named with it and not required.
  - **IND annual report:** the `ind_annual_report` record (21 CFR 312.33).
  - **Type A/B/C meeting packages:** the type-neutral FDA meeting core.

  AnA, the Authoring picker and the governed outline therefore read one outline.
- `market-support.ts`: a class is offered as **Author documents for this market**, never "Build
  and sequence", with its own reason. ICH ("ICH / Global") is stated as a harmonised market for
  the ICH classes. Project creation gives a class no submission spine, and "Add a market"
  refuses one (`NOT_AN_APPLICATION`).
- `required-sections.ts` and `vault-coverage.ts` say that a class is not a CTD dossier. Without
  that, E3 §5.1 or M11 §5.2 would be read as Module 5 requirements.
- `document-class.ts`: the catalog's "ICH / Global" agency label resolves to `ich`. Without that,
  a CSR authored in its project would not bind to the project's governed CSR.

The full after-matrix is `routing-after.txt` (columns: catalog id | family | program type |
doc_type | offer | pack).

## Limits, stated

- **No pack is reviewed by a regulatory professional, and none was re-read against regulator
  text in this change.** eCFR, fda.gov, ICH and Cornell LII are unreachable from the build
  environment. Each pack's `uncertainties` says this and names its source record. Confidence is
  `low` for platform records and blueprints, `medium` for E3, E6(R3) App A, E2F and E2C(R2)
  headings (recalled), and `high` only for the ICH M11 outline, which an earlier session checked
  against the regulator's text.
- **Still routed to the NDA outline:** US PMR (its existing outline is a protocol), the 15-day
  ICSR (an E2B message, D7's transport), the EA (a Module 1 component), SUPAC (a guidance
  framework, not a filing), the US Module 1 regional row and four device QMS records under FDA.
  Accelerated approval, rolling submission and priority review are NDA/BLA submissions, so the
  NDA outline is correct for them.
- **DMF Types II–V** share the harmonised Module 3 outline (`mod3:ich`). Type I has not been
  accepted by FDA since 2000. A per-type DMF outline is not built.
- **A document already bound to a superseded version keeps its outline** (the composite FK makes
  the record true). New projects get the new versions.
- **Completion:** readiness counts every node, so an optional section that does not apply holds a
  document below 100%. The design docs place not-applicable on an evaluated fact, never a client
  toggle (`docs/design/SUBMISSION_REQUIRED_DELIVERABLES_UI.md`). This is a product decision for
  the founder and is not built here.
- **Not on staging** (D1 owed).
- **Pre-existing, unrelated:** these fail identically on trunk with and without this change:
  - `server/routes/__tests__/authoringTemplateStartFrom.test.ts`, 2/8: "The section insert
    returned no exact saved identity".
  - `server/services/regulatory/__tests__/market-support.test.ts`, "no line names … AS2". The
    FDA ESG sentence has named AS2 since `e1f3fd42`.
  - `tests/schema-contract/tenant-isolation-sweep.contract.test.ts`: pass 1 stops at
    `migrations/20261014_notification_recipient_receipts.sql` ("relation mdx_notifications does
    not exist"). This change's migration applies before that file in pass 1.
- **Affected suite:** 107 files, 2,129 tests: 2,122 pass, 4 fail and 3 are skipped. The 4
  failures are the three above plus the picker test this change updates, which now passes 13/13.
  The canonical typecheck (`typecheck-no-regression --incremental`) reports 0 errors.
