Two edits to the tests after this run:
 1. "names each row's program, so the Vault can open that project…" became "names each row's project as its own
    organization records it, and its status in the Vault's words". The draft asserted a `programId` field per row; the
    design dropped it (no screen needs it), so the case now asserts `prog`, `status` and `author`. Reworded, it pins
    fields the route already returned, so it would pass at HEAD: it guards the shape, and the other seven server cases
    prove the scoping (each red at HEAD above).
 2. "with no project open, focuses the row in the organization view, by id or by name": an unknown id is re-read once
    before it is a miss (the Live Drive re-read rule), so the last expectation waits for the deferred outcome and counts
    the re-read instead of expecting a synchronous failure. At HEAD the case fails earlier, on the absent view.
