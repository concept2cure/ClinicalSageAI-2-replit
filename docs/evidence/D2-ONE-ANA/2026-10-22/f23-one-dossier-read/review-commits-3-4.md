## Confirmed, and fixed in the commit that files this record

**The detail read said 'no_sections' for a program with sections when its URL id was upper case.** UUID_RE is case-insensitive, and the access gate lowercases the id itself. But readDossierFigures keyed its rows by `d.project_id::text`, which Postgres prints in lower case, and looked them up by the raw id. Before the range the same miss gave a bare null. The range turned it into a definite claim that there is nothing to count. The list and the create pass ids from the database, in lower case, and were not affected.

Fix: readDossierFigures matches ids case-insensitively, so every caller is covered (server/services/c2c/dossier-read.ts). Pinned by `projects-readiness.test.ts` › "an upper-case id in the URL reads the same measured figure".
