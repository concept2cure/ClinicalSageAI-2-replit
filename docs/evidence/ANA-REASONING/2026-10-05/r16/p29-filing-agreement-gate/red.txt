A FALSE RED, FIRST, AND WHAT IT HID
-----------------------------------

The first run of these cases also reported "3 failed | 3 passed" — the same
tally — WITH the gate in place. The cause was not the gate: the helper that
rewrites the filing ran a bare UPDATE, and

  c2c_snapshot_section_version: app.actor_id GUC required for section content
  change (Part-11 attribution)

aborted it. So the first "red" proved nothing about the gate, and the matching
tally made it look like it had. The helper now sets `app.actor_id` and
`app.reason` the way the real filing-side route does, and resets them, and the
red above was re-established with a working helper.

Worth keeping: the trigger that broke the helper is the governed store refusing
an unattributed write. The harness had to be made to act like the real door
before it could test anything about it.
