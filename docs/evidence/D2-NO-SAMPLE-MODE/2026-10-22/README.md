## What already exists

- `ci:fixture-fallback` and `ci:no-mock-in-prod-routes` block in `.husky/pre-push` and
  CI. They catch a fixture *import*. They cannot catch a value made up inside the
  code: a default confidence, a "system" actor, an unread result reported as "none",
  a score over nothing assessed. That is what this entry covers.
- Sample mode and its datasets were already gone (2026-10-14 entry).
- No new capability was added. Every change fixes or completes an existing route,
  service, migration or surface, or deletes a seed or script that wrote invented
  records. The commit for each deletion names what replaces it, if anything does.

## What changed

155 commits, found by a codebase-wide inventory and then fixed. Each one does one of
four things:

- **A fact nobody recorded stays unrecorded.** It is shown as null, "not recorded" or
  "not determined", never as a default such as 'moderate', 'system', 'NDA', the
  current year, 0.7 or 100%.
- **A failed read is an error**, not an empty result ("no recalls", "low risk", "no
  schedule", "not found").
- **A score or verdict covers only what was measured.** Nothing assessed is not
  "ready", "compliant" or "on track".
- **Tenant, actor and identity come from the session**, never from a request body,
  organisation 1 or a hard-coded name. Reads are scoped to the caller's organisation.
