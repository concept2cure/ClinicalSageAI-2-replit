## Contract completed

The service accepts a lazy request getter, authenticated numeric user and actual admitted project. It resolves current email and project membership, exact document/project and section/document relationship, and the appropriate VIEW grant before templateSource/guidance reads. Section-only/email-only grants, read-only actors and frozen documents remain readable. Denied or malformed selectors never fall back to a parent/client classification. Header reads retain only templateSource, not unrelated import provenance; no section prose is read and no transaction is opened on the shared optional request executor.

An exact section carries the canonical validator's retained source, guide, verification state, manual/narrative/unverified policy and actual saved code/status. Assembly source wins, and parent-only current outline/limits are omitted. Non-registry CRF components keep registry null. Identity-only positive flags remain unverified; known negative/manual restrictions remain visible, including historical exact E3 references. The entire fixed-heading/reference-only JSON block is limited to16KiB UTF8 without clipping. Whole-document current/earlier-outline behavior remains bounded separately; numeric non-authoring Protocol Development type statements remain no-DB surface context.
