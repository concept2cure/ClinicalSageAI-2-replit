# Source identity semantics review

Read-only review of the approved `CONTRACT.md`, 16 October 2026. The contract names assessment baseline `990a687c6`. Application implementation was not reviewed as final at this checkpoint. This reviewer owns only `semantics-*` evidence files in this folder and does not alter application code, providers, migrations, Git history or baselines.

## Contract assessment

The bounded change addresses a concrete integrity gap: original-file identity and an extraction's length cannot identify the extracted text. Binding the entire extraction, absolute half-open excerpt coordinates and exact excerpt prevents same-length corrections inside or outside the excerpt from silently becoming the earlier evidence. New writes use V2 only; historical stored references retain their weaker checks without fabricated historical hashes. This is a source identity checkpoint, not a model-use, scientific-support, regulatory-approval or agency-acceptance claim.

This is applicable to biotech, pharma, medical device and diagnostics records without adding a filing-pathway decision. The content identity rules must operate identically on Japanese, accented European languages, Greek scientific symbols and supplementary Unicode characters. The SHA input must not undergo case folding, whitespace normalization or Unicode normalization. Only hexadecimal digests and UUID spelling are normalized.

## Required clarification before claiming exact identity

**Ill-formed Unicode must fail closed.** Node's UTF-8 encoding maps distinct unpaired UTF-16 surrogate values to the same replacement character. Consequently, an unrestricted JavaScript string can change while its UTF-8 SHA-256 and UTF-16 length remain unchanged. The smallest compatible remedy is to reject ill-formed full extraction strings in the canonical identity factory. This preserves the contract's UTF-8 digest format. A valid full extraction may still have a selected UTF-16 slice whose boundary bisects a surrogate pair: the exact full-extraction digest plus coordinates binds the slice, and the contract does not promise that every slice is independently well-formed Unicode. The standalone control in `semantics-surrogate-utf8-control.json` demonstrates the encoding behavior; it is not an application regression test.

The approved lead clarification takes the stricter option for excerpts too: the factory refuses a split-pair excerpt, and the producer may move a selected boundary inward by at most one code unit to retain an intact pair without replacing source text. Final review follows that clarified contract; it does not require acceptance of a split-pair excerpt.

The lead identified a related final-check boundary: a valid replacement character U+FFFD can be replaced by an unpaired surrogate after the initial factory call while a metadata-only UTF-8 digest remains equal. The bounded final checkpoint should therefore use the same canonical actor facade with `includeText: true`, recompute identity from its current body with the validating factory and keep that body internal. This avoids relying on the usually valid UTF-8 PostgreSQL storage/driver assumption and does not change the facade's authority or API; the existing metadata facade already reads the underlying text internally. A final-check test should distinguish this from an ordinary changed-digest refusal.

## Final patch review checklist

- New parsers and direct verifier entry points validate complete V2 identity and strictly typed safe-integer coordinates before any await. Legacy parsing is a separate saved-record-only route. Unknown versions, partial digest fields, and a V2 marker left at either group or source must refuse; removing identity from a new request must never select legacy behavior.
- Complete removal of every V2 marker from a trusted persisted record cannot by itself be distinguished from a genuine historical record. The patch should not claim historical provenance tamper detection or silently promote that record to exact extraction verification.
- Factory hashes the complete current extraction and `text.slice(start,end)`, measures bounds with JavaScript UTF-16 length, and rejects empty spans, excess width and mismatched total length. Producers and verifiers use the same factory. No caller-supplied source text, qualification or authority becomes persisted verification.
- Loader snapshots IDs, actor/open-project identity and query selection before awaits. It preserves canonical current actor/private-parent admission. After assembling the selection it rechecks every selected source with the canonical actor facade and validating factory over current text, including original identity, extraction identity and original-availability/disposition caveats, then repeats actor/program scope checks. A concurrent retained-data withdrawal must not return a stale assertion that the original file is available.
- Direct verification snapshots parsed reference objects and spans before any await, and returns newly built verification objects rather than aliases to mutable input. Matching digests establish identity only after canonical current source access and original-byte checks succeed.
- New save and source-linked rendition paths use one existing-module reservation helper: program advisory lock, Vault source-store SHARE reservation, then verification, held through the existing commit or rollback. A predecessor row lock alone does not reserve a future successor insertion.
- Persisted groups explicitly distinguish V2; returned legacy verification stays `legacy_original_bytes_only`, never `exact_extraction_and_span`. Historical audits are not rewritten. Manual records without source references keep their existing path.
- Batch output and audit/provenance retain version, digests and absolute span while removing raw source text. Tool schema accepts late-document absolute offsets; runtime owns relative width, aggregate budget and uniqueness checks.

## Evidence boundaries

Owner tests and held-out tests should demonstrate same-length changes inside and outside the selected span, absent/incorrect digests and versions, new-write downgrade attempts, exact Unicode UTF-16 spans, a window beyond offset 80,000, unchanged V2 round trips, retained `keep_data`, private/wrong-tenant/wrong-program/current-version refusals, final-recheck changes and mutable input controls. Reservation-order assertions from mocks prove call order only. Genuine PostgreSQL concurrency, rollback and runtime-role observations must be reported separately. The final review remains pending the lead's frozen cross-file patch.
