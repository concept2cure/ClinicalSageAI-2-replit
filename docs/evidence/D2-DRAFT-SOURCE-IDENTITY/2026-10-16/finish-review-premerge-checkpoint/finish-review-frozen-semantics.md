## Integrated behavior

- Shared V2 types and the one identity factory bind original-file identity, the whole extracted string, and the exact half-open UTF-16 excerpt. The factory rejects unsafe or inconsistent bounds, oversized/empty windows, ill-formed full strings and split-pair excerpts before UTF-8 hashing. It does not normalize source characters. The producer can move a selected surrogate-pair boundary inward by one unit, then records the actual unchanged slice and original coordinates.
- The strict new-write parser requires complete V2 identity, own data properties, safe-integer coordinates, distinct source IDs and the established per-selection width/aggregate budgets. It creates private, frozen reference/span snapshots. Unknown request text, qualification and authority fields are dropped. Direct verifier calls use that same parser before their first await; actor identity is reduced to its current user ID before an awaited import/read.
- Historical decoding is reachable only through the saved-record verifier. An unversioned saved group with historical sources retains the original byte/length/current-authority semantics and is never given today's extraction digests. A V2 group or any remaining source identity marker requires complete V2; partial or unknown versions refuse. Complete removal of all V2 markers from trusted stored provenance is not distinguishable from genuine historical provenance by this mechanism. No tamper-detection claim is made for that case, and historical records/audits are not rewritten.
- The producer snapshots caller selection, actor/project context and section query before awaits. It obtains metadata and text through the canonical actor facade, checks original bytes, current version, source eligibility and extraction identity, then privately reloads actual current text for every selected source after selection assembly. It recomputes the validating identity, preserves or refuses changes to original-availability/disposition and extraction caveats, and repeats actor/program admission. This closes the valid-U+FFFD versus unpaired-surrogate digest alias at the final text checkpoint without adding a public body field or catalog API.
- Save verification continues through the canonical current-actor/current-parent loader with explicit `userId`, project and `currentOnly` scope. It recomputes both V2 hashes from server text and constructs returned verification independently of caller authority assertions. Retained eligible text remains usable when its original is unavailable, with honest availability caveats.
- New source-linked saves and existing saved-source reservations call the same helper: canonical program advisory admission, then Vault document/catalog SHARE locks, then source verification. The authoring transaction invokes this before regulated inserts and provenance serialization. Source-linked export/working-copy/file-to-Vault callers retain their existing reservation and verification paths. Those locks last until the existing commit/rollback; the helper introduces no migration, provider or alternative implementation.
- New saved groups explicitly carry `sourceReferenceVersion: 2`, `current_at_save` and `unassessed`. Batch receipts remove source text while preserving the V2 fields and absolute span; audit identity retains only hashes and coordinates. Existing bounded figure/claim diagnostic quotations remain established provenance. The tool schema accepts late-document absolute coordinates while runtime parsing enforces relative width and aggregate budgets.
