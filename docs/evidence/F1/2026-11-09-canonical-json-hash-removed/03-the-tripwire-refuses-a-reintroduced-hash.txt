The tripwire exists to refuse a hash put back into this module. A replacement
here would be written under the same constraint that produced the original
defect — five client files import stableStringify, so a static node:crypto
import would reach the browser bundle — and would reach for the same dynamic
require, which does not exist in an ESM runtime. So: shown refusing it.
