# O01 content and extraction consumer contract

This scope advances D5 governed records and D6 current tenant admission. The five existing services have mounted legacy HTTP consumers but no current launch client consumer was found. This work repairs their actual transport; it does not activate a new surface or qualify a provider.

Document Data Center upload and tag updates retain their existing response fields and add `meta.auditTrail`, using the canonical audit outcome. Fresh current membership is checked before multipart reception. The store is organisation scoped and has no project field; no project binding is invented. Tag updates retain the same tenant predicate on read and write.

CER creation and version updates retain their row fields and add `meta.auditTrail`. The existing facade forwards that actual outcome. Device lookup and report writes require the same organisation. Section updates cannot overwrite tenant, author, identity, lifecycle or approval fields. Version history and content changes must remain one atomic operation; critical approval/signature work is outside this draft-only scope.

Keyword extraction returns its actual audit outcome. The sole extraction handler supplies the real document/project/organisation arguments and checks current project admission. The service resolves the exact current eligible canonical artifact, verifies its content hash and requires submitted text to match. The response carries the actual artifact identity, version and hash. Source linkage failures are disclosed, not represented as proof that no source exists. Existing source evidence is read only under its current tenant/project scope. Recorded term usage is explicitly not a semantic consistency assessment.

Figure generation retains statistical-estimate refusals and approved-model routing. Its actual handler supplies the typed source references, raw data and preferences expected by the service. Generated content is distinguished from saved content. The canonical provenance primitive requires artifact and provenance to commit together. The approved writer now enlists both in one transaction. Ancillary audit failure after a confirmed save does not turn the completed save into a retryable generation failure. Unconfirmed COMMIT preserves the computed draft, identifies the artifact for reconciliation, refuses automatic regeneration and discards the physical request connection through its canonical owner.

Extraction jobs carry real creation and terminal audit outcomes in the same object returned by queue/status/list. The queue remains process local and is labelled as such; audit events do not imply a durable restartable job. Queue and status handlers verify current project access, and source lookup includes the actual project and tenant. Failed computation remains failed; lost ancillary audit after completed artifact writes remains a completed job with a warning. No new job store, migration, dependency or provider activation is introduced.

Every queued job runs in its own existing roleless organisation job scope. A private transient callback reuses the original verified request principal only through canonical admission, which reads fresh membership and project permissions on the instrumented pool. It borrows no released request connection. Admission runs before provider work and before content writes, and its callback is removed at termination. The native proof enqueues under completed HTTP requests, runs a second tenant and revokes a queued creator.

The native positive computation exposed the existing governed import refusal: `originSurface import_pipeline is not allowed for documentClass evidence_memo`. That fence remains in place. No origin/class policy was widened to enable the pipeline. Completion remains unqualified, as does general inheritance of future source dispositions by derived table/section artifacts. The corrected artifact source labels do not claim to close that shared ancestry gap.
