# QMS request database qualification

The [published contract](qms-request-db-contract.md) is implemented: every QMS HTTP database read, ordinary mutation, controlled Authoring context, permission evaluation, signer check and signed transaction now receives the canonical request client. Missing request database admission fails closed. Non-HTTP change-control defaults and the default shared audit path retain their existing behavior. Query-only executors supply rows; they are not asserted to provide a complete pg.Pool or its callback/configuration overloads.

This is an explicit connection consistency remedy. The native negative control shows an unscoped raw pool cannot read enforced tenant records. The same test proves the canonical runtime pool **does** read them with its authenticated AsyncLocal scope and enforcement enabled. A request-client-only fixture is therefore insufficient evidence for a general production global-reader outage; that broader inference is withdrawn.

The actual native test is `tests/db/mdx-qms-request-rls.dbtest.ts`. It asserts TLS and the `app_service` role's non-superuser/non-BYPASSRLS identity, then verifies the deployed QMS/Authoring/training tables have both RLS and FORCE RLS enabled. Actual authentication establishes tenant ALS, current membership and a LazyRequestDbClient. The positive workflow creates a draft and canonical blank sections/grants, reads the register and editor target, enters review, verifies a different signer's real password, writes a bound signature, reads immutable retained content, acknowledges the effective version and counts current training. Database mutation attempts are refused for reviewed prose and retained snapshots.

Foreign exact-document editor/history reads, acknowledgments and programme claims refuse without returning prose or the authored UUID. A current unshared member remains denied despite an admin claim in the signed token. The missing-request-client case is a separate synthetic admission-contract control. Native investigation also found foreign history returned `200 []`: this did not disclose content, but disagreed with the exact-resource contract. The route now checks the owned, live parent first and returns 404 for a foreign/missing parent; genuinely owned unsigned histories still return `200 []`.

Ordinary training acknowledgment completes before its separate audit attempt. The native failure fixture intercepts only the captured request query at the audit INSERT after the actual business INSERT. The acknowledgment remains durable; no additional audit row exists; the HTTP response reports `AUDIT_ROW_NOT_PERSISTED` without caught text. A fresh authenticated request then writes both its acknowledgment and real chained audit entry. This is controlled query-fault evidence, not a claim of a real transport outage or ambiguous COMMIT-response qualification. Signed critical actions continue to write their audit and signature inside the business transaction.

Older mounted-route fixtures now attach their existing admitted query executor explicitly. Their original signed/refusal, rollback, audit-loss and legacy API retirement assertions remain. The legacy positive review fixture supplies a saved synthetic Authoring copy and the required reason; its authorization/ledger boundaries are declared test seams. The service regression executes actual PostgreSQL-WASM SQL through a rows-only executor: foreign removal changes nothing, owned removal succeeds, repeat removal fails and the soft-deleted row remains. These fixtures qualify caller and SQL contracts, while the native suite qualifies FORCE RLS.

Scope limits: native draft prose is a trusted synthetic fixture, not native editor-save evidence. Real editor behavior has separate [QMS UI evidence](qms-ui.md). This native QMS ceremony verifies password signing; shared native password/MFA/TOTP and protocol ceremony evidence is [separately recorded](protocol-native-request-proof.txt). Native request tokens use the local development HMAC fallback, which does not qualify production asymmetric-key distribution or rotation. All tenants, credentials and requests are local synthetic fixtures. The final harness preserves its uniquely named signed/audit records and disables no policy or immutability guard. An earlier discarded fixture run borrowed privileged synthetic-row cleanup; that was corrected before the final qualified run and must not be represented as never having occurred. No live tenant, provider, agency submission, deployment or destructive production action was used.
