# F05 — submission continuation contract, 14 October 2026

Scope: reconnect the existing persisted submission orchestrator to its release-signature and asynchronous CSR completion paths (D2/D5). The signed-package export verification chain remains unchanged.

New runs retain their original input snapshot with a canonical digest and tenant/program scope. Snapshot identity is write-once. A resume reads that stored input, checks its digest and run identity, verifies the caller's current program/organization access, and acquires a database session advisory lock keyed to organization and run before executing the existing resume driver. A concurrent request reports busy; a finished run is returned without repeating downstream effects. Missing legacy async inputs require regeneration rather than guessing.

Write authority is current organization membership and the canonical governed-write role, followed by current program authority. A retained program lead cannot keep write authority after downgrade to viewer. Fresh selected-program runs, resume, legacy start and regeneration all enforce the route write gate; worker continuations recheck the original actor's current database role before effects. Read discovery retains its existing organization-scoped privacy policy.

Signing persists the existing governed signature first, then attempts the same guarded continuation. A failed/busy continuation is reported separately from the successful signature and can be retried without signing again. A stored signature does not make a package exportable until the existing snapshot/seal/signature verification advances `package.sign` to complete.

The eCTD Compile surface starts a run for the selected program and sequence, discovers its recorded runs, gathers release credentials through the shared signing ceremony UI, and displays explicit wait/failure states. While asynchronous work is pending the visible surface polls the saved run status and offers a guarded continuation check; returning to the surface discovers retained waiting work. It does not fabricate completion or silently start replacement runs.

Implemented backend: private immutable input/pause-output receipts; org/run session advisory claim; current program and original actor authorization; sealed receipt and frozen release verification; original CSR job-id/project/actor binding; governed CMC source revalidation before asynchronous assembly; production resume, selected-program start and discovery routes; automatic continuation after durable CSR completion; signature success followed by guarded continuation with a separate retry outcome. Modern legacy frozen releases hydrate their exact signed record; old asynchronous runs without original receipts require regeneration.

The existing signed-export gate remains unchanged and refuses any sign step that has not reached verified completion. Run and regulated step-audit persistence now fail closed before further effects. Pause outputs preserve the exact refined Module 3 narrative without repeating AI or CSR enqueue. Successful signing returns its recorded timestamp, including idempotent/race outcomes; unavailable timestamps remain null.
