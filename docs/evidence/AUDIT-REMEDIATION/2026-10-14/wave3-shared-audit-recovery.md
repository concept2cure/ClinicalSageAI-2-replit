# Shared audit outcomes and connection recovery

This supplements the third-wave contracts. It qualifies the changed paths only; it does not certify every independent audit writer or the production estate.

The input safety guard now carries the actual high-risk observation audit result. Observation mode continues normally and emits a bounded warning through the existing AnA SSE protocol when persistence is unconfirmed or only the tamper-proof store succeeded. Enforcement mode retains the original refusal and its receipt. The actual chat hook preserves those receipts on both successful streams and HTTP refusals. Internal database diagnostics are not displayed. The tenant-impersonation refusal also retains its actual audit result without changing the refusal.

Borrowed request transaction clients now pass an error release to their canonical lazy owner. The owner marks the request connection unusable synchronously, then discards the physical connection; it does not issue cleanup SQL after an uncertain COMMIT. A query queued during acquisition cannot subsequently run on that discarded connection. Healthy borrowed releases retain normal request ownership.

The ancillary request-audit helper distinguishes a pre-COMMIT refusal from a lost COMMIT acknowledgement. The former attempts rollback; a failed rollback discards the connection. The latter returns `unconfirmed: true`, never claims rollback, and discards the connection. The existing `AUDIT_ROW_NOT_PERSISTED` compatibility code continues to drive client warnings. `persisted: false` means durable persistence was not confirmed, rather than proving that no row exists. Shared warning copy and the global UI notice now say “could not be confirmed” and ask for history review before retrying.

The generic Part 11 audit helper first writes its mandatory device history, then returns the actual ancillary general-audit mirror receipt with the existing device row. The mirror has explicit organization, actor, entity and primary history identity. Its failure cannot falsely report that the already-durable device row failed. Malformed identities no longer silently become actor/entity zero; explicit system actor zero remains supported. Current access checks reuse the canonical current-membership reader, including active user and organization status. Integrity results and denied-access results retain their actual mirror receipts.

The unused legacy validation-report methods no longer invent four passing tests, operational component assessments, validation dates or a validated system version. They state `NOT_ASSESSED` / `NOT_RUN`, with absent execution dates. Recording a report request is not validation evidence. The actual electronic-signature transaction and its signing ceremony are unchanged by this generic helper repair.

Native proof covers deployed device-history RLS, chained-audit tenant enforcement, the tamper-proof writer's tenant guard, actual stored rows/HMAC seals, current secondary-organization membership and revocation, and recovery after failure. The tamper-proof table has a global append-only design and no FORCE RLS policy; this proof does not claim otherwise. The request-audit COMMIT-loss control performs a real COMMIT, confirms the row still exists, observes physical backend eviction and verifies that later lazy queries refuse. See [the native receipt](o01-part11-native-proof.md).

The named discarded-outcome guard now also parses bare unawaited expression statements and includes untracked production TypeScript files during a working-tree audit. Arrow returns and arguments retain their results and are not bare discarded statements. Promise chains, aliases, assigned-but-unused values and independent void-returning sinks still require semantic review. The zero-budget baseline does not qualify those other mechanisms. The 58 actual repaired sites and four retired unused budget slots are counted separately.

The SQL predicate recognizer retains exact per-caller imports, unshadowed bindings, literal aliases and actual interpolation spans. The three content callers may use only their canonical artifact eligibility builder with alias `a`; CSR callers retain their reviewed Vault builders and alias `d`. No SQL value allowance or interpolation baseline was increased.
