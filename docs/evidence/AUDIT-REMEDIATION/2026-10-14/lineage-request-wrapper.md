# Protocol request transaction lineage recognizer

The actual Protocol route now runs its controlled mutations through `governedScoped` on the canonical request client rather than checking out another pool connection. Its BEGIN, domain callback, governed action, COMMIT and ROLLBACK remained present and shared the same request client. The old lineage CI recognizer required the literal `.connect()` shape and rejected this working transaction.

`check-lineage-save-gate.mjs` keeps Protocol's service in its existing GUARDED list and validates both transaction owners. Only its explicitly configured Protocol router uses the new TypeScript AST recognizer in `lib/lineage-request-transaction.mjs`. Other owners retain the existing checks. The recognizer reads the actual helper declaration and exact request/client import, requires direct acquisition before entry with refusal on missing context, validates the awaited BEGIN→callback→governance→COMMIT sequence and catch ROLLBACK on that same client, verifies the forwarding helper passes unchanged arguments, and verifies both prose writers await the unchanged callback client. A wrapper name, a comment mentioning BEGIN or an unrelated transaction cannot satisfy it. Missing declarations, transaction steps, detached calls, client substitutions or rebinding refuse. The existing service lineage-gate check remains separate and unchanged. There is no baseline growth, new dependency, guarded-path removal or production-source edit.
