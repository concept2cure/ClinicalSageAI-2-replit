# Existing socket regression adaptation contract

The two existing suites `as2-delivery-outcome.test.ts` and `icsr-gateway-transport-after-send.test.ts` cover delivery ambiguity and retained-state classification. The FDA suite keeps actual local mTLS sockets, TLS client-certificate refusals, response timing, resets and separate-process servers. The ICSR suite keeps its explicit simulated HTTPS event harness. Neither suite is an agency qualification or cryptographic interoperability proof.

The revised production contract distinguishes the pinned agency CMS certificate from a separately configured TLS trust anchor. Fixtures must provide the latter explicitly. These network-focused suites may replace only CMS envelope/receipt primitives with clearly documented deterministic test doubles; the shared production delivery classifier, TLS implementation, MIC matching and persisted-state decisions remain actual code. A primitive receipt double represents cryptographic verification already established by the separate `as2-cms.test.ts` suite. Its returned notification still goes through the production message/disposition/MIC parser. CMS signatures, encryption and tamper rejection remain tested independently with real OpenSSL and generated certificates; no production cryptographic path is bypassed by this test-only adaptation.

No production edits, provider calls, dependency changes, commit or deployment are part of this test scope.

The same explicitly isolated boundary applies to the existing FDA client-account, hardening and ambiguous-delivery unit suites, plus the base ICSR transport suite. Those suites retain account/credential selection, bundle-integrity refusal, raw agency-response retention, governed rollback, disposition/message parsing and negative/ambiguous outcomes. Where a test asserts which signing key is used, it must assert the exact credential passed to the CMS primitive; the unrelated raw-RSA helper is no longer evidence that a production CMS envelope was signed. Their receipt doubles preserve declared MIME framing and feed the production parser; they do not replace the delivery classifier.

Verification: the stale-fixture run exposed 28 failures before it was interrupted in an existing long separate-process case; the first failure was the new system-TLS default rejecting the local self-signed chain (`/workspace/audit/transport-socket-fixture-before.log`). That interrupted run is not a completed baseline count. After the explicit TLS fixture and documented CMS isolation adaptation, 89 tests passed across both adapted suites plus the actual OpenSSL CMS suite (`/workspace/audit/transport-socket-fixture-after.log`, 6.53 seconds). No assertions, timeout bounds, classifications, TLS-refusal cases or duplicate-send-state requirements were weakened.

The four unit suites failed 56 tests and passed 34 before their fixture adaptation (`/workspace/audit/transport-unit-fixture-before.log`). Final compatibility passes 101 tests across those four suites and the actual OpenSSL suite (`/workspace/audit/transport-unit-fixture-final.log`, 2.76 seconds). The hardening database double now retains actual receipt metadata; acknowledgement download must return exact original receipt bytes with their recorded MIME type, rather than relabeling a multipart response as a bare notification. The sponsor-key test now asserts the production CMS call receives the exact configured key/certificate and message, replacing an unrelated direct raw-RSA helper invocation. Explicit-refusal and ambiguous-delivery assertions are retained; the service owner restored the evidence-first explicit-refusal fallback during review. These scoped semantic doubles are not agency qualification or cryptographic success evidence.
