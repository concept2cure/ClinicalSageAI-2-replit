# F22 / D05 / D06 source contract before implementation

The code-defined report taxonomy and its generated deployed seed contain 61 report types. Canonical `reportAvailability` is the sole authority for whether each has a run engine and which declared scopes that engine supports. This work inventories each type from those sources; it does not create engines or change report content, run dispatch, migrations, grants or paid-plan policy. Prediction-family registrations are distinguished from executable governed runs, even where a separate advisory assembler exists. Current-context catalog counts must describe the filtered applicable catalog, not suggest that all 61 types can execute for every program.

The top-level `services/ai`, `services/workflow`, `services/compliance` and `services/documents` subtrees have no external non-test runtime consumer in the audited current tree. Their algorithms are retained as source references. The unvalidated predictive factory/engine and both parallel legacy workflow engines are retired as executable entry points: construction refuses with a stable explicit unavailable code before a detector, database read/write, timer, notification, worker or simulated completion can run. No adapter is invented to bypass tenant authorization, provenance, delivery or artifact locks. Actual shipped tasking, notification, authoring, approval, dispatch and reporting implementations stay authoritative and are unchanged by this convergence decision.

Deferred launch surfaces remain deferred. Their inventory and catalog descriptions identify implemented parts, missing outcomes and the current canonical surface a user can reach. Existing routes or retained prototypes are not described as complete production workflows. No API prefix, launch surface, feature flag or entitlement is widened. Engineering outcomes that still need qualification or authoritative data remain partial/blocked rather than being called completed.

Regressions must execute the real prototype entry contracts and prove refusal occurs before effects or completion, verify all 61 inventory entries against canonical scope availability and generated seed, and check that the catalog distinguishes engine-backed, currently runnable, unavailable and prediction entries. Root owns integrated build/typecheck and browser qualification.
