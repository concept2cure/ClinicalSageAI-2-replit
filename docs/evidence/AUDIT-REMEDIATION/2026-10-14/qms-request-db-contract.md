# Native QMS request database completion

F01/F02 native integration uncovered an executor gap: QMS HTTP methods issue global pool queries rather than use the authenticated request's pinned connection. A supplied, enforced request session does not scope another pool connection. The global instrumenter can also bind an AsyncLocal tenant scope when enforcement is enabled, so a request-client-only native proof must not be described as every possible full-auth production path failing. The remedy removes this dependency and qualifies the explicit request-client contract against the deployed policies.

Every QMS HTTP read, ordinary write, controlled Authoring context, document permission evaluation and signed lifecycle transaction must use the canonical requestPgClient/requestConnectable. Missing request database context must fail closed; there is no global fallback or request-controlled scope override. Existing organization predicates, project/object permissions, signature meaning, current membership, password/MFA/lockout and audit semantics remain.

Change-control helpers take an optional structural query executor, passed explicitly by HTTP; internal reads use that same executor. Existing non-HTTP defaults are preserved. Conditional removal uses returned database rows, without claiming an optional executor supplies a complete pg.Pool result. Controlled-document constructors accept the minimal query/connect/release contract their existing implementation consumes; a pinned request client is not cast into a full Pool.

The read-only governed-document binding helper likewise consumes a query-only executor. Its existing SQL and binding decisions remain; it no longer requires unused pg callback/query-config overloads. The shared row adapter supplies only the rows that these callers consume. Ordinary QMS mutations pass the canonical request connectable to `recordAuditRow` after their business operation completes. That optional mode uses the existing chained writer on a separate audit transaction and reports a bounded warning on failure; signed and controlled critical transactions keep their audit enlisted with the domain write. Default callers of the shared audit helper remain unchanged.

Shared Part11 helpers remain canonical and receive optional executor injection from their coordinated owner. QMS signing passes the same request executor for authority and credential verification, then uses the pinned connection for its existing atomic document/change, ledger and signature writes. The electronic-signature policy is not reimplemented in this router.

Verification must include the actual non-superuser, non-BYPASSRLS app_service role and deployed FORCE RLS policies; owned create/read/editor/review/approve/version/training flows and foreign-row controls must run against native PostgreSQL. A raw unscoped/global query is a negative control, never the positive workflow. No policy disabling, app_super_admin GUC, new dependency, migration or real agency transaction is authorized by this remedy. Scoped mocked tests pin caller contracts, but cannot qualify FORCE RLS.
