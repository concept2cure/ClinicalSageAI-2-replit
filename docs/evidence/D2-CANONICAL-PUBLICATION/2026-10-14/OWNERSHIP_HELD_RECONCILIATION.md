## Automatic recovery preselection reconciliation

The final sweep extension obtains anchor candidates through the existing canonical `listProgramAnchorCandidates(q, {orgId, eligibility: 'non-deleted'})`. It groups all recorded candidates by program and includes a program/workspace pair only when the group has exactly one valid canonical anchor with a recorded workspace. An invalid or second anchor does not become valid by selecting a convenient row. The serialized frame is bound as JSON parameter `$3` in both candidate and omitted-diagnostic queries. Excluded source IDs move to `$4`; runtime identifiers never enter SQL text. Source ID, limits, mode and closed SQL shape are captured before the new asynchronous frame lookup.

For a program-bound workspace, the fixed SQL predicate compares the source with that frame **before ordering/LIMIT**. A misleading older source cannot consume the slot of a valid newer candidate. The workspace-only legacy predicate remains unchanged. This frame is **candidate preselection, not an authorization grant or a held relationship**: every selected row still goes through the processor's canonical ownership, exact anchor, original-byte, claim/lease, lock and final reuse checks. The source/query row itself is not trusted to attest access or identity.
