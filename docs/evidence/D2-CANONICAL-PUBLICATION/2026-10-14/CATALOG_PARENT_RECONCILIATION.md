# Catalog held ownership and captured-parent reconciliation

The catalog writer now calls the canonical `programInOrganization` helper with `{forShare: true}` on its existing transaction connection. It retains the program row before the project row and policy rows are held. Current actor admission, table-lock ordering, private-project checks, exact source checks and before-COMMIT readmission remain. A focused control verifies the canonical held query is after table reservations and before the project row hold; a parent removed at this check refuses before catalogue metadata, audit or DML.

Programme-bound captured sources compare their recorded workspace with `projects.client_workspace_id`, even when that workspace number differs from the integer project ID. Workspace-only legacy sources need the exact recorded chat-upload origin, metadata artifact identifier, provenance file identifier and same-organization artifact/file/project association. The legacy workspace must match that recorded artifact project, as the canonical CRE helper requires; numeric coincidence alone supplies no relationship. Exact artifact binding cardinality and all same-organization program anchors are evaluated before intersecting permitted programs. Candidate queries return only identity fields, not raw metadata, titles or file headers. Canonical upload admission checks every recorded parent before COUNT/LIMIT and repeats for the full admitted file set before disclosure.

Known unresolved associations are omitted from actor-filtered discovery; the selected canonical parent operation independently refuses them. Unknown query/policy state remains unavailable. Ambiguous retained legacy bindings refuse. A private additional upload parent cannot enter counts or displace an accessible result. Final parent revocation refuses a page already loaded.
