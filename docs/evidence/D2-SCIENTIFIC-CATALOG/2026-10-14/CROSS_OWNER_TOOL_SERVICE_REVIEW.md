## Reviewed source-boundary changes

1. The actual registered `catalog_project_document` description handler requires a resolved target before calling `completeCatalog`. It snapshots `target.programId` into a local server field before awaiting the open-project scope check. Body-supplied `program_id`, `expectedProgramId`, actor or reviewer fields are not forwarded as authority.
2. `completeCatalog` privately copies its arguments before the first await. Its exact source loader returns only a recorded same-organization document with a live owned parent. `catalogableExpectedProgram` compares that freshly loaded source against the server's admitted program before coverage, embedding and writer handoff. A move from admitted program A to accessible program B does not become a B write.
3. A move after source loading preserves A in the final writer's source snapshot. The canonical governance writer separately admits and locks the exact program/source inside its transaction and refuses the changed source; the serving-layer fixture deliberately mocks that final writer and therefore does not establish SQL race or RLS behavior by itself.
4. `loadDocumentForOrg` now selects and filters exact recorded document organization, checks the returned row's organization, and requires a live owned parent in all branches. Source-family currentness remains explicit for preview; existing legacy/historical read behavior is not silently presented as typed approval.
5. Discovery/listing SQL applies document organization plus owned live-parent scope before its window totals. `assertCatalogListingScope` checks the returned recorded document and parent identity and null deletion status before projecting document descriptions or recall. A malformed row fails visibly rather than being dropped while fabricated completeness/totals are returned. Bootstrap recall inherits the same guard.
6. Preview uses the same current persisted member/project admission helper on its read-only transaction connection, loads current-only exact eligible text, and preserves full aggregate byte-bound read coverage. Its results explicitly carry `persisted:false`, `reviewState:'not_recorded'` and `scientificQualification:'unassessed'`; context diagnostics are separate from exact transcription. It neither embeds, writes a description nor accepts a fact. Flag-off remains the default.
7. The tool JSON schema/runtime parser separates description from explicit verification preview. Preview rejects unrelated write/identity/review fields, requires bounded candidates and refuses a response too large to deliver whole. Description retains legacy compatibility while refusing fact candidates outside explicit preview mode.
8. The current catalog GET/review HTTP block forwards the session actor and exact shown extraction hash; it rejects a supplied non-string hash. The existing panel returns that digest, requires a matching persisted decision receipt, and shows legacy context-not-recorded scope while preserving who confirmed/corrected the whole header. Current data eligibility and original-file availability are distinct.
9. The lead's narrow error-transport fix adds optional `safeOutcome:true` to the shared wrapper and the tools owner enables it only for catalog/read/list/search registrations. Exceptions return a static explicit failure and `outcome:'unconfirmed'`; no raw error, SQL/private metadata, rollback claim or invented persisted flag reaches the caller/model. Normal successful results and existing explicit refusals pass through unchanged. Other shared-wrapper callers retain their preceding behavior.
