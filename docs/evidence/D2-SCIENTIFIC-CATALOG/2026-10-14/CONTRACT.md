# D2 scientific catalog: source verification preview and write integrity

14 October 2026. Local work on canonical `concept2cure-v2`, baseline `87b27c897c5d1be20b0527009bcaf425ebbf3af6`, preserving completed recovery/storage/D7 changes. This is the first bounded implementation of the broader scientific-catalog specification, within the existing Vault catalog and AnA catalog tool. It moves D2 source verification and truthful usability; it does not implement D5's future independently accepted fact events.

## Outcome and limits

1. AnA can request an explicitly named, read-only source-fact verification preview inside the existing `catalog_project_document` tool. It checks exact source/anchor/value/context bindings, never stores or accepts facts and never confirms a catalog header. There is no new table, migration, model, tool name or surface.
2. Existing catalog suggestion/review writes freshly admit the actor and exact current eligible source inside their short transaction. Derived-source checks bind original bytes and exact stored extraction; changed text, withdrawal, supersession, scope or zero-row update cannot produce a successful catalog/audit receipt.
3. Existing key_data and real legacy confirmation/correction history remain unchanged. Arbitrary legacy keys are never converted to semantic properties. Current readers and the existing Vault catalog panel disclose that the automatic legacy check covers values, while label/context verification is not recorded. A confirmed header is not typed scientific fact acceptance.
4. Preview context is a bounded supported-source relation, not scientific truth, applicability, qualified method, regulatory release or agency acceptance. Models propose strings; deterministic engines check. No arithmetic, conversion, pooling, denominator inference, accept/reject tool or fabricated original-page/table attestation is added.
5. Prototype preview is server-gated by `ANA_CATALOG_SOURCE_FACT_PREVIEW=1`, default off, alongside the existing catalog gate. Tests explicitly enable it. Domain-expert and deployment qualification remain separate; no live provider call is needed for this slice.

## Pure source-fact interface

Core owner creates browser-safe `shared/ana/catalog-facts.ts`, with the proposed specification's schemaVersion1, five meaning families (`pharma_clinical`, `cmc_result`, `device_test`, `ivd_diagnostic`, `ivd_analytical`), strings as written and source-statement origin. The clinical transport is a serializable projection of existing clinical frames/vocabulary, never a browser import of server runtime. Source anchors have exact document UUID, original SHA-256, extracted-text SHA-256, half-open integer range and exact quote. Locators unsupported by current server evidence are refused rather than guessed.

Public pure functions are re-exported through canonical document-catalog-core/service:

- `validateSourceFactBatch(input: unknown)`: strict shape and bounds, 1..50 candidates, at most20 witnesses/fact, at most2,000 chars/quote and100,000 serialized chars/batch. Unknown discriminants/semantic paths/status/actor/computation fields refuse. Deterministic computations explicitly remain unsupported.
- `verifySourceFactCandidate(candidate: unknown, source: CatalogFactSource): CatalogFactVerification`, where the server-owned source is `{documentId,contentHash,extractedText,extractedTextSha256}` plus any explicitly supported extraction caveat. No candidate selects another source, supplies authoritative text, or attests to its own checker/result.
- Output identifies checker revision, candidate digest, exact source/text digest, separate transcription/context checks (`passed`, `failed`, `not_established`) and stable safe reason/path codes. It always identifies `scientificQualification:'unassessed'`, `reviewState:'not_recorded'`, `persisted:false`.

Malformed shape, wrong source/digest/range/quote or value absent from its exact value anchor rejects the batch before any result is described as source-bound. Context failure or missing/unsupported context returns a visible diagnostic preview, never accepted/usable-as-reviewed. No clipping of evidence is permitted.

All mandatory nonnull context values require verified permitted witnesses. A word/value appearing remotely in the document or somewhere in a large multi-subject quote is insufficient. Automatically pass only a supported, unambiguous same-clause/row relation with explicit subject, property and required context; unsupported tables/headers/languages stay not_established. Reuse the existing clinical extraction/frame logic for clinical relations, with adverse frame comparisons. Preserve measured-result versus specification/criterion, comparator agreement versus sensitivity, assay/specimen/cutoff/population/reference/denominator, CMC lot/method, device configuration/software and analytical design/unit distinctions. Bounds/ranges/approximation and source-written precision/exponents cannot become scalar values.

Existing `verifyKeyDataAgainstText` and the 3-argument `assertCatalogWriteAllowed` retain their legacy meanings. Added scope fields must describe check coverage without fabricating a past pass or reinterpreting historic confirmation.

## Existing-tool preview operation

`catalog_project_document` adds optional `record_type:'description'|'verification_preview'`, default description. Description keeps its existing required inputs. Preview requires document_id and fact_candidates; it accepts no description/key_data/write/review fields. Facts supplied without explicit preview mode refuse instead of being silently discarded into the legacy write. Tool JSON schema and runtime parser agree on both branches.

Preview requires the existing catalog gate, identified current member, Vault write role (no widening of existing tool authority), canonical open-project admission, exact current eligible owned Vault version and supported extraction. Resolve actor/project/model from serving context; body-supplied scope/identity never grants access. Load exact text through the canonical service, compute its SHA-256 server-side, preserve the existing byte-based full-read coverage gate and evaluate the candidates without embedding/audit/write. Return explicit preview-only result even when checks pass. Existing read receipts are aggregate byte-bound delivery evidence, not extraction-specific or current-actor/current-turn proof; no stronger claim is made.

`read_project_document` adds exact extracted-text SHA-256 to its current document/byte identity envelope, enabling anchored preview requests. Read windows and full-read gates use the actual stored text length, rather than trusting stale catalog character counts. It must not claim a receipt for truncated or undelivered output. Oversized diagnostic output refuses the whole preview with a reduce-batch notice rather than clipping checks. Current description results and recall carry an explicit legacy check scope/context-not-recorded disclaimer; typed preview results are not flattened into key_data or saved description.

## Canonical catalog write fence

Take a private JSON snapshot of description/key_data/proposer fields and exact loaded text digest before asynchronous embedding. `completeCatalog` passes the expected exact extraction digest to `writeCatalogSuggestion`; it cannot submit successful in-memory checks for a subsequently changed source.

Use short READ COMMITTED transactions, existing disposition program advisory lock, then explicit catalog ROW EXCLUSIVE and Vault documents SHARE reservations before fresh source/catalog reads. Preserve that order on both suggestion and review writes to serialize withdrawal and successor/move/extraction DML. Hold the exact live parent/program/project admission rows as appropriate. SHARE on documents is an initial global contention tradeoff, not a scalability qualification.

Use canonical project admission/active membership/private-project policy on the transaction executor and keep current Vault role checks; do not copy policy or query globally while holding the transaction client. Recheck exact recorded organization/program/id, valid byte digest, catalog/source hash agreement, source version-family currentness, canonical data/original availability and expected extraction identity. Preserve completeCatalog's existing refusal to change a keep_data original; preview may read retained eligible text with explicit original availability caveat if canonical read policy permits it.

Recompute legacy value verification against the locked current text. Audit the exact source/text and candidate/key_data digest, checker/check scope and server-derived proposer. Require exactly one conditional UPDATE RETURNING receipt before a success audit/result; a zero-row/RLS refusal is not vector fallback. Only a genuinely missing/unsupported vector operation may fall back under its savepoint; admission, persistence and receipt errors propagate/refuse. Capture/suggestion/review and chained audit stay atomic.

Review retains whole-record semantics and required existing revision. The new panel sends optional `expectedExtractedTextSha256`; when supplied it must match the exact source shown. Legacy callers without it retain only their prior whole-header revision decision and never gain an extraction/context-verified status. Historical decisions remain visible on the read path with current-use eligibility/caveat, not retroactively erased. Any read failure remains visible rather than empty/assessed.
