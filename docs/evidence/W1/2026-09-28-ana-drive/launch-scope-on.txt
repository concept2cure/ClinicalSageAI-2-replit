D2 — AnA with launch scope enforced, as production runs
2026-09-29, concept2cure-v2, local stand-in model (harness/), headless Chromium

── Why ──────────────────────────────────────────────────────────────────────
LAUNCH_SCOPE_ENFORCE unset means on in production and off everywhere else
(server/services/entitlements/launch-scope.ts). Every battery run before this
one had it off, so every screen was open. With it on, screens outside the
launch catalog are locked. A deployment the founder tests on runs with it on.

── Where AnA's navigation targets land ──────────────────────────────────────
Each of the 97 navigation targets (shared/navigation) was resolved through
the client's own resolver to the screen the shell mounts:
  34 land on a launch-catalog screen;
  63 land on a screen outside the release (Biostatistics, Inconsistency,
     the device and product-development workstreams, …);
   0 land on no screen.
With launch scope on, the shell sends AnA the locked set with every turn
(locked_screens). list_app_screens withholds those screens, and navigate_to
and act_on_screen refuse them as not_available.
