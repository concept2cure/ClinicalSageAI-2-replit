A cut-off answer says so — 2026-09-28 (fourth pass)

What was wrong: AnA's stream route never read why the model stopped writing.
The gateway reports it (finishReason). The canonical check for "cut off with
more to say", isTruncated in server/services/ai-gateway/finish-reason.ts, was
used by document drafting and batch drafting but not by the chat stream.

An answer that hit the model's length limit, or a stream that stalled
mid-answer, therefore reached the person as a finished one. The status line
read "Finished", no note was shown, and no Continue was offered. The next turn
was handed it as a complete answer. With models that always think (Opus 5.5)
or think by default (Sonnet 5), the thinking counts against the same budget
(6,144 tokens at balanced effort), so long answers are where this lands.

The change uses the existing stop-reason channel end to end:
  - server/services/ana/tool-trace.ts turnEndingReason: a loop that ended for
    want of tools, on an answer isTruncated() calls cut off, ended
    "answer_cut_off". Any stop the loop already reports stands. An unknown
    finish reason is not treated as a cut: that would be its own fabrication.
  - server/routes/ana-ri/stream.ts: the finish reason of the latest model call
    (the first answer, then each round) is kept, and the ending is decided after
    the loop. That is before the done frame, the turn-record warning, the saved
    message and the run row, all of which read it.
  - Words on every surface that had words for a stop:
      transcript note  "AnA's answer was cut off before she finished it. It
                        ends where it stopped." (with Continue)
      status line      "Stopped: answer cut off · <time>"
      next turn        "Your previous turn had its answer cut off before it
                        was finished. …"
      turn record      "The answer was cut off …, before AnA finished writing
                        it. What the person saw ends where it stopped."
  - No migration: ana_runs.stopped_reason is text with no CHECK.
