D2 — an action AnA sends to another screen gets that screen's answer
2026-09-29, concept2cure-v2, local stand-in model (harness/), headless Chromium

── How an action on another screen runs ─────────────────────────────────────
act_on_screen names a screen and an action. When the person is on another
screen, the client's action bus stashes the action and navigates there
(applySurfaceAction, client/src/concept2cure/v2/surfaceActions.ts). The screen
mounts and registers its handlers, and the bus tries the action at once. That
is while the screen's first read is still in flight, so a handler that needs
the data answers `retry: true` and the bus holds the action.

Only two things re-try a held action: the screen registering, which has
already happened, and the screen calling notifySurfaceActionReady. An action
still held after 20 s (PENDING_ACTION_TTL_MS) is reported "did not become
ready in time". The server stops waiting for the screen at 10 s
(MOVE_SETTLE_MAX_MS) and tells AnA the move is not confirmed.

── The audit (every action, from the source) ────────────────────────────────
Checked with the TypeScript parser, no model involved:
  - 96 actions declared in shared/navigation/surface-actions.ts; every one has
    a handler (88 as literal keys, 8 built from template keys in
    pdev/surfaces/Workstream.tsx).
  - Every handler reads exactly the params the registry declares (94 by the
    parser; the Usage and Billing tabs share one named handler, which reads
    `tab`, as declared). The bus passes declared params only, so a mismatch
    would be silent; there is none.
  - Every registration's screen id is the one its actions resolve to, through
    the client's own alias resolver. There are no mismatches.
  - The ready signal is where it breaks. 32 of the 53 handler registrations
    can hold an action:
    - 2 never signal:
        client/src/concept2cure/v2/surfaces/Biostatistics.tsx ('biostatistics')
        client/src/concept2cure/v2/surfaces/Inconsistency.tsx ('inconsistency')
    - 16 signal only when the read succeeded (`if (!x.loading && !x.error)`,
      and on the program journey `&& !empty`):
        AgencyMeetings, BiopharmaJourney, BiopharmaProject, ChangeAssessment,
        CrlLibrary, CroPortfolio, DecisionLineage, DocJourney, HaqManager,
        LabelingPi, Orchestration, PrecedentEngine, Pyramid, SafetyNarrative,
        ShadowReview, SourceTracer.
      Each of their handlers refuses honestly when the read fails ("The
      sponsor roster did not load, so there are no sponsors to select from."),
      but a held action was never re-tried, so it never got that answer.
    - PublishingCenter already signals on ready or error; it is the pattern.

── The fix ──────────────────────────────────────────────────────────────────
  - Biostatistics and Inconsistency signal once their read has settled,
    whether it succeeded or failed. Each mirrors the condition its handler
    holds on.
  - The 16 signal once loading has settled, and the handler gives its own
    answer: the action on a good read, the honest refusal on a failed or
    empty one. PrecedentEngine keeps its `applied` condition; its handler
    refuses on its own when no search has been run.
  - Nothing else changed. No handler, and not the bus.

── Found, not fixed here ────────────────────────────────────────────────────
The Inconsistency board cannot read any program opened from the Projects
screen. The screen sends the open program's id, a UUID (BX-301 is
0db36813-b1f7-4b5a-a2a1-4c96fb927100). GET
/api/governed-intelligence-inconsistency/projects/:projectId/inconsistency
accepts only a numeric id from the legacy `projects` table and answers 400
"A valid numeric projectId is required". So the board shows its error state
for a person too, and AnA now says so rather than "not confirmed". The server
already maps a program to its project through projects.regulatory_program_id
(programFilingContext, server/services/biostatistics-bridge/bridge-service.ts).
BX-301 in the demo seed has no such project row. The board is governed
intelligence, outside the launch catalog; this is left to its owner.
