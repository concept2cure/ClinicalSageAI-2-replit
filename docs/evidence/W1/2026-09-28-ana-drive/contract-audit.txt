AnA's requests against the Messages API contract — 2026-09-28 (continued)

Why: the browser battery ran against a local stand-in for the Anthropic
Messages API, and until this pass the stand-in enforced one rule (an empty
non-final message is refused). A request shape the real API refuses would have
passed the battery and failed the first real turn. The stand-in now refuses
everything below, each rule taken from where the API documents it:
  - claude-api skill: shared/models.md, shared/error-codes.md,
    shared/prompt-caching.md
  - live docs (fetched 2026-09-28): api/messages, build-with-claude/effort,
    build-with-claude/mid-conversation-system-messages,
    build-with-claude/prompt-caching

Rules enforced (400 unless noted):
  - model id: retired ids (Claude 3 family, Claude 2, Opus 4.1 from
    2026-08-05) and unknown ids -> 404 not_found_error
  - max_tokens: a positive integer, at most the model's output maximum
  - unknown top-level, message, content-block, tool and thinking keys
    ("Extra inputs are not permitted")
  - empty content in any message but an optional final assistant one; empty
    text blocks; cache_control on an empty text block
  - first message from the assistant (error-codes.md)
  - role "system" in messages: only on Opus 5.5, Opus 5, Opus 4.8 and the
    Fable/Mythos 5 family; never first; must directly follow a user turn; must
    end the array or precede an assistant turn; text only
  - tool_use without a tool_result in the next message, and the reverse
  - tool names ^[a-zA-Z0-9_-]{1,128}$, unique; input_schema.type "object"
  - more than 4 cache_control breakpoints
  - tool_choice any/tool on Opus 5.5 and Fable 5.1; tool_choice without tools
  - temperature/top_p/top_k on Opus 4.7+, Opus 5.x, Sonnet 5 and Fable
  - thinking "enabled" (budget_tokens) on adaptive-only models; "disabled"
    on Opus 5.5 and Fable, and on Opus 5 at effort xhigh/max; "adaptive" on
    Haiku 4.5; budget_tokens < 1024 or >= max_tokens; temperature other than 1,
    or top_k, with budget thinking
  - output_config.effort on Haiku 4.5 and Sonnet 4.5; xhigh on Sonnet 4.6 and
    Opus 4.6
  - assistant prefill on Fable
The stand-in also streams the way a real adaptive model does: a thinking block
(empty, closed by its signature) ahead of the text and the tool call, and a
ping event.

Not a rule: consecutive user or assistant turns. The live API reference says
"Consecutive user or assistant turns in your request will be combined into a
single turn", so the skill's error table, which lists them as a 400, is out of
date on that point.
