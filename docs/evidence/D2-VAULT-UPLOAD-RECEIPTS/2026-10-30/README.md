## What already exists

- `client/src/concept2cure/v2/useVaultUpload.ts` is the single shared hook for Vault upload/check-in and the retained device pathway attachment consumer. `uploadOne` currently trusts HTTP 2xx, catches JSON failure as null and then returns ok even without a document identity; `upload` publishes stored/succeeded and the downstream consumers act on those. The existing complete-send/no-reply `unknown` outcome, per-file status and batch wording already handle uncertain writes honestly. Extend those; do not add a recovery ledger, upload engine, endpoint or automatic retry.
- `v2/vaultIngestTransport.ts` owns one authenticated multipart XMLHttpRequest and upload progress; `IngestReply` already provides status/ok/json. It deliberately does not own clinical filing policy or application receipt interpretation. Keep auth headers, multipart, progress and complete-send behavior.
- `v2/surfaces/Vault.tsx` uploads staged files and new versions through the hook. It opens only returned recorded IDs, refreshes for succeeded files and removes a check-in offer on success. `VaultUploadStaging.tsx` already renders unknown results distinctly and retains the selected file. `VaultVersions.tsx` reuses the same check-in flow.
- `mdx/surfaces/pathway/PathwayPanes.tsx` calls the same hook and adds a local dossier attachment only for succeeded filenames. A false shared success therefore reaches a life-sciences workflow, rather than staying inside a helper.
- `server/routes/vault-ingest.ts:274` returns success=true, document and filing at 201 for a new row, 200 plus reupload for already recorded bytes. `server/services/vault/vault-ingest-types.ts` defines the actual producer record; `vault-ingest.service.ts:734` returns the generated document UUID, exact requested programId, stored title, assigned version, extraction state and actual stored placement. Authorizations, source/target rechecks, idempotency, version links, storage and chained audit remain server-owned.
- `v2/surfaces/Etmf.tsx` is an existing direct caller because it supplies an explicit TMF document code and then files a separate artifact. It already requires a returned document ID but has distinct receipt/recovery behavior. It is inventoried, not silently folded into this filename-derived hook or claimed fixed by this bounded patch.
