# Existing AnA biotech workflows — three bounded repairs

Published scope is the canonical `concept2cure-v2` product only. This W3/D4
delivery strengthens existing contracts; it does not qualify every biotech use
case, declare D4 green or add a tool, model, surface or integration.

## What changed and why

| Boundary | Demonstrated failure | Correction and retained controls |
| --- | --- | --- |
| CMC advice → cited regulatory record | With the actual 608-tool launch pool, 50-tool limit and self-drive pins, ordinary Q5C-version and Module 3 potency questions omitted their required record tools. Context-free follow-ups lost them too. | The three existing deterministic read tools join the existing always-on core, matching the persona's pre-advice rule. Governance still filters first; denied/hidden tools cannot be resurrected. The cap stays 50 and other workflows retain their tools. |
| Retrieved/drafted source ID → canonical evidence source | A direct ID above the database's SERIAL/int32 maximum raised PostgreSQL 22003 and aborted the whole batch, including its valid references. Both direct numeric and `cre_source:` drafting inputs reproduced it. | Reject unavailable numeric IDs before the integer-array bind. Preserve valid sources, an honest dropped-source explanation, inclusive maximum, tenant ownership and captured-data eligibility. Numeric direct keys cannot alias another source through artifact metadata. |
| Statistical input → reported assumptions | Explicit valid `attritionRate: 0` remained zero in the calculation but was called a default by the normalizer and public `compute_sample_size` response. | Default attribution now uses the same absent/null condition as the existing default. Supplied zero remains the user's assumption, with no dropout inflation. Missing/null still use and name 0.15. All computation and validation bytes stay unchanged. |
