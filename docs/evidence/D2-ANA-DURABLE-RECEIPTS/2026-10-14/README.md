## Implemented behavior

A genuine server deferral receives a private stable admission ID and tool-use context before any await. Model/body/caller metadata cannot mint this identity. Existing single-window reads produce one exact UTF-16 range. The pure shared descriptor supports one to eight sorted disjoint ranges, immutable private copies and a canonical SHA256 fingerprint. It records actor/role, original and extraction identities, actual slice hashes and the unchanged host payload hash; it stores no source body, filename, prompt or model output.

The new public integer-tenant ledger has no source/user/programme/project cascade. Normal UPDATE/DELETE/TRUNCATE refuse in SQL. FORCE tenant RLS and application current-actor/private-project admission are separately checked. Identical stable-ID retries acknowledge the same descriptor; changed, inaccessible, ambiguous or unconfirmed persistence cannot earn a new receipt count. Append-helper results remain provisional until the transaction caller confirms COMMIT.

`ANA_DURABLE_SOURCE_READ_RECEIPTS=1` selects the new writer and remains off by default. The existing legacy writer/coverage retain their meaning. The selected path repeats canonical fresh actor/source/extraction/payload checks under short source/actor reservations. Optional legacy insertion uses a savepoint: only narrowly classified legacy table permission denial can leave a committed V2 record with an explicit absent-legacy outcome. Unknown integrity/transport or COMMIT outcomes remain unconfirmed. Cancellation and same-round observed source refusal preserve their existing safeguards; notification failure cannot erase a real commit.

Actor history uses the canonical current read wrapper, applies actor/programme/exact-ID filters before count/rank/LIMIT and re-admits access before return. It includes only the current actor's own history in currently accessible projects. Historical metadata survives source removal; viewing it does not grant a new source read or current-use authority.

The complete tenant exporter discovers this customer-data table. Canonical offboarding uses a fixed NOLOGIN purge door, with runtime EXECUTE and no purger membership. Source-table barriers precede fresh organization/status and legal-hold reservations; final-export metadata is pinned after waits. Current status/retention/export/holds must permit deletion, the final status UPDATE must acknowledge one valid returned row, and erasure/status/audit commit atomically. A missing participating door or unconfirmed count/status refuses rather than reporting successful erasure. Schema registration precedes the final isolation tail; runtime privileges and boot trigger checks use the existing canonical lists.

## Meaning and boundary

The only checkpoint is **host_budget_admitted**. It establishes local exact-source admission metadata, not gateway invocation, exact provider delivery, replay, model comprehension, scientific review or government acceptance. Gateway IDs can span retries/fallback and provider adaptation can change payloads. No API-calling SDK/gateway/host invocation implementation was changed or executed in this increment.

The shared range DTO does not introduce new passage selection, table/page anchors, whole-document service or authoring/generation/save/export range receipts. Earlier conversation replay, memory/profile policy and other platform readers retain their separately stated scope. Legacy receipts are not backfilled or promoted into extraction-sensitive coverage; scientific preview stays off and scientifically unassessed. Receipt hashes cannot reconstruct erased source text. Privileged schema administrators are outside the runtime append-only guarantee.
