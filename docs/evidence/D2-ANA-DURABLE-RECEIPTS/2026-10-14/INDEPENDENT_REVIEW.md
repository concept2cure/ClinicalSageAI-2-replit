## Established behavior

The DTO is a private immutable copy, canonicalized and fingerprinted before asynchronous digest work can observe caller mutation. Exact IDs, positive int32 identities, role/context bounds, own data properties, unknown/sparse/accessor refusal and one through eight ordered nonoverlapping late UTF-16 ranges are covered. Canonical JSON is checked against an explicit reference and independent SHA256. Acceptance time and source body are absent from the descriptor. The ranges/storage controls establish representation and hash integrity; they do not add an actual multi-range source reader or structural/page anchors.

The default settlement path selects V2 only for the exact enabling flag. Actual server deferral mints the admission ID and reported tool context; model/caller fields cannot fabricate private origin. Retries preserve that ID. The actual selected viewer writer hashes the stored late slice and unchanged handler payload, records the fresh persisted role, inserts V2 and acknowledges it only after COMMIT. The actual legacy receipt policy denies viewer INSERT; its precisely identified refusal is isolated with a savepoint, the durable transaction commits, and the outcome states that legacy history was not recorded. The new ledger is not merged into legacy catalog read coverage.

Zero/null/ambiguous/mismatched INSERT confirmation, unrelated legacy permission/integrity failures, revocation, same-length extraction drift, cancellation and uncertain COMMIT cannot earn an acknowledged new count. Genuine PostgreSQL cancellation after INSERT rolls back both ledgers. Concurrent same-ID identical retry waits for the first session and returns historical idempotence; a changed payload/fingerprint under the same ID waits and refuses without rewriting the row.

Actual actor history filters organization, actor and admitted programmes before counts and LIMIT. Newer private/other-actor serving contexts neither displace the authorized row nor contribute to its count. ## Scope limits

The only durable checkpoint is **host_budget_admitted**. No SDK, AI gateway, host invocation or provider request was changed or executed by this increment. No request/dispatch ID, provider acknowledgement, model comprehension, scientific decision, human review or agency acceptance is inferred from a row. A previously committed admission can remain when later source refusal withdraws a round; that history is not proof the model received it.

The source fixture uses synthetic minimum precursor tables and synthetic core programme functions. Audit chain/sequence/INSERT and purge transactions are actual application SQL, while the HMAC seal is synthetic. Runtime tenant RLS for this installed ledger, application sharing admission and controlled offboarding are separately demonstrated; this is not deployed all-table RLS, a fully provisioned database gate, mounted API authentication or production workload qualification. The complete export is complete for the actual synthetic schema, not every deployed product table.

The ledger cannot reconstruct erased text. Reported thread/tool context is not authenticated conversation proof. Original SHA comes from the exact stored source identity; this review does not reopen or prove binary storage. Current access checks remain bounded point-in-time checks with no transaction spanning provider work. Prior transcript replay, provider dispatch/replay checkpoints, authoring/export range adoption, structural/multilingual retrieval and scientific fact decisions remain separate increments. The existing source/catalog/preview gates retain their legacy meanings, and no old receipt is backfilled or rewritten.
