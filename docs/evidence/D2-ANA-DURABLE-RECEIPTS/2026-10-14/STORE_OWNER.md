# Immutable admission metadata store and actor-history owner

The approved D2 durable receipt contract governs this owner slice. Only the new store/history helpers and their focused controls are edited. Existing source-access/catalog/receipt-host files, shared DTO/schema/migration files, lifecycle, providers and public tools remain with their declared owners.

`appendSourceAdmissionReceipt(q,descriptor)` snapshots through the canonical shared V2 validator before any await, computes the immutable descriptor fingerprint and appends metadata with a stable receipt ID. A new outcome requires exactly one actual INSERT RETURNING row and an independently validated matching descriptor/fingerprint. A conflict performs only an exact ID/organization/actor lookup. An identical visible row returns `already_recorded`; changed, inaccessible, ambiguous or uncertain storage refuses. The helper never UPDATEs a row and stores no quoted source, filename, dossier, prompt or handler/model body. The transaction caller owns source/actor reservations, cancellation and real COMMIT; this helper's result alone is not a committed or provider-served claim.

`listSourceAdmissionReceiptsForActor(input,{documentId?,receiptId?,limit?})` uses the existing canonical actor read wrapper. SQL restricts organization, current actor and canonically accessible uniquely anchored programmes before window totals, ranking and LIMIT. Exact document/receipt selections are additional filters, never authority. Stored descriptor shape and fingerprint are checked before projection. Rows from another actor, tenant, programme or exact selection refuse the page. The canonical wrapper re-admits the pinned scope before returning.

History entries contain only `{descriptor,receiptSha256,acceptedAt}`. The page identifies `host_budget_admitted`, `historical_admission_only` and provider delivery `unestablished`. It reads no source table, so valid metadata survives source removal; viewing it grants no current source-use permission or new receipt. The original admitted role/context remains history even when the actor's present role differs. Projection snapshots acceptance time and metadata before async fingerprint verification, and returned values are frozen.

`STORE_FAIL_FIRST.log` records three expected baseline failures observed before this implementation: the existing legacy insert could not acknowledge a stable durable ID/outcome, persisted no extraction/payload fingerprint and had no stable-ID retry protocol. These show the new storage capability was absent. They do not reinterpret the legacy table or imply it was intended to provide V2 proof. The preserved `legacy-gap.baseline.test.ts` uses its dedicated evidence-only Vitest config and stays outside ordinary test discovery.

Focused owner controls cover real-returned-row count semantics, identical/mismatched retries, foreign/inaccessible conflict, private input/returned-row mutation, malformed DTO/range/fingerprint, actor/private-programme page filters, invalid selection, source-removal history, unknown policy/SQL state, final revocation and exact historical checkpoint wording. These are controlled sequential query/policy fixtures; independent held-out and genuine owned PostgreSQL concurrency/schema/role evidence are the control tower's separate proof.

`STORE_TESTS.log`: Node 22, 60/60 focused controls across two suites. `STORE_TYPECHECK.log`: four owned roots with repository ambient declarations/imported dependencies, zero selected-scope diagnostics; this is not a whole-repository typecheck. `STORE_ESLINT.json`: zero errors and zero warnings. `STORE_SOURCE_MANIFEST.json` records exact argument arrays and final hashes of the four owned roots. The production store/history and owner controls are frozen after these checks. No production deployment, installed-role or whole-platform qualification is claimed.
