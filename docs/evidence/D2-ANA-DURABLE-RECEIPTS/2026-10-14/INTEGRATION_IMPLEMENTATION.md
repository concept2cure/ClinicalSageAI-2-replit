# Existing source-read receipt integration

14 October 2026. Source-tools ownership: `read-receipts.ts`, `source-read-receipt.ts`, their focused controls and shared legacy host-budget fixture. Shared V2 validation, storage, schema, lifecycle, hosts, SDK and gateway implementations are outside this owner's edits.

`deferReadReceipt` synchronously generates a private UUID and copies the server tool-use context. Caller/model fields with these names are ignored. A private in-process origin registry preserves that identity through the sanctioned immutable snapshot and retry path. Copying visible fields into an arbitrary object does not mint a genuine V2 admission. Direct legacy callers remain compatible without new fields.

`writeGuardedReadReceipt` chooses the existing legacy writer unless `ANA_DURABLE_SOURCE_READ_RECEIPTS` is exactly `1`. The default-off path does not invoke the new store. The flagged writer reuses the same program/source table reservations and canonical read-only actor admission, checks the actual current extracted text and unchanged payload, then builds the strict V2 descriptor using the fresh persisted role and exact stored slice hash. It passes the existing single offset window as one UTF-16 range. No provider call, gateway ID, model comprehension or scientific decision enters this checkpoint.

The flagged transaction appends through the canonical store and attempts the optional legacy receipt under a savepoint. Only SQLSTATE 42501 with the precise legacy table permission/RLS denial message is tolerated; a supplied schema/table mismatch, function permission error, integrity failure, zero/mismatched conditional INSERT or transport failure is unconfirmed. Savepoint recovery itself must succeed. No legacy receipt is claimed when it was denied.

The selected writer returns `{checkpoint:'host_budget_admitted',receiptId,outcome:'recorded'|'already_recorded',legacyReceipt:'recorded'|'not_recorded_permission_denied'}` only after the actual COMMIT response. An unknown COMMIT outcome earns no acknowledged count or success notification. Settlement counts new logical admissions, does not count an identical durable retry as new and does not add legacy and V2 rows together. The optional `onReceiptSettled` callback reports the committed distinction; callback errors cannot erase a real count or turn a failed persistence into success.

Cancellation before admission/append/COMMIT preserves the existing refusal behavior. Cancellation after acknowledged COMMIT retains the committed history. Typed current-source refusal still invokes the existing source-refusal callback and stops later writes in that round. Existing host handoff and aggregate legacy coverage meanings remain unchanged. V2 records are not merged into `getReadCoverage` or catalog/preview approval gates.

The inspector extraction initially copied an early return into the read-only handoff verifier, skipping COMMIT. Independent review and root TypeScript/lint found this while implementation was in progress. An explicit actual handoff COMMIT/no-ROLLBACK assertion observed the failure (`integration-handoff-commit-fail-first.log`), then passed after the misplaced return was removed. The verifier retains `Promise<void>` and its original short transaction lifecycle.

Validation: the initial legacy baseline passed 44 controls; the new 21-case corpus observed nine meaningful failures before the integration fix. Final focused verification passed all 65 controls across three files. Scoped ESLint over six owned files has zero errors and warnings. Root's scoped production-target TypeScript check covers both owned production helpers; no full-repository or new-test typecheck is inferred. `integration-owned-final-manifest.json` binds the exact six files and focused reports. Independent/real PostgreSQL source-role, idempotency and commit evidence is provided separately by the review/root owners.

The shared read-delivery fixture adds the selected-writer seam while staying explicitly legacy-only. It qualifies budget and prior compatibility behavior and supplies no durable storage proof. No existing serving host, SDK/gateway implementation or API invocation was changed by this owner. No schema/store/shared/lifecycle file, live client database, deployment, commit or push was touched.
