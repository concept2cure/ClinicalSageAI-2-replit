# S9 — Tasking: what already exists

**Package:** S9 (tasks: what is due, and what is mine), with D6 (the Tasks page), D1 (Home, the tray) and S4 (AnA)
**Date:** 2026-11-13
**Head read:** `da35d66fc1` and the commits pushed after it on 2026-11-12
**Why this record exists:** RULE 3, and plan §3, which asks each spine package for a filed "What already exists". S9
had none. It is filed before any design or code for founder decision P-131.

## The founder's words (2026-11-12)

> "Tasking must be on the left rail as it sits above or includes all project types and more and be connected to every
> global features across all of the platforms"

> "And when I log in to my tasking page I should see everything needed and by priority and a suggestion and greeting
> from AnA who must also keep track of all assigned tasks and even unassigned but needed tasks for our clients"

Read as four requirements:

- **R1.** Tasking is a place on the left rail, global: across every project type and client type.
- **R2.** Tasking is connected to every global feature: work that arises anywhere shows up there.
- **R3.** Opening the Tasks page shows everything needed of the person, in order of need, with a greeting and a
  suggestion from AnA.
- **R4.** AnA keeps track of every assigned task, and of work that is needed and has no owner.

## How this record was made

Five readers each read one part of Tasking and recorded, with file and line, what each existing piece does today and
what it does not. Each reader also listed the gaps it saw. Then skeptics tried to refute every gap by searching for an
existing piece under any other name (work item, assignment, action, deliverable, obligation, commitment, queue,
inbox, my work). A gap is listed below only if it survived that. Nine did not, and they are listed too, with the
existing piece that already does the job, so nobody rebuilds it.

Nothing was run. Every statement here comes from reading code, and each reader's "did not read" is at the end.

## The answer in one paragraph

Tasking exists and is large. "Tasks" is the third place on the rail, for every client type. Behind it are one task
store (`unified_tasks`), one cross-store read (`server/services/unified-work/unified-work-view.ts`), a governed write
path, a board with four views, a per-person read (`server/services/tasking/my-work.ts`) shown in the top bar and on
Home, and an unbuilt but recorded design for the page (`.design/claude-convergence/D6.md` §D6.A, slice D6-1). **No gap
below needs a new screen, route, table or AnA tool.** What is not true today: the page opens on everyone's tasks in
no order of need, has no greeting, leads with a critical path nobody designates, and leaves out the approvals and
reviews the tray shows; work from several areas never reaches it; and AnA cannot read the task store at all.
