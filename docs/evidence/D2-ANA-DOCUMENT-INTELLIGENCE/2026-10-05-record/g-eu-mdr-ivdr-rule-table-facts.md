**Platform convention, not regulator text.**
- MDR results return `class: null` with `missingFacts` when the kind of invasiveness or the duration is missing, unless a rule already gives III. This applies decision 1 of DECISIONS.md (fail closed).
- Rule 2 marker matching is platform convention. ISBT designations are matched case-insensitively. Traditional names (C vs c, K vs k) are matched exactly.
- (Fix round 2.) Alias table for `bloodGroupingMarker` (platform convention, `readRule2Marker` in device-classification.ts). The engine reads one value or a list, and each value is read whole or token by token.
  - **→ D, by the listed markers it denotes.** System names map conservatively to every listed marker in that system. The Annex itself names the "ABO system", "Rhesus system" and so on, so a device that "determines ABO" determines listed markers:
    - `ABO` → ABO1–3.
    - `Rh` and `Rhesus` → RH1, RHW1, RH2–RH5.
    - `RhD`, `Rh(D)`, `Rh D`, `weak D`, `partial D`, `Du`, `D` → RH1.
    - `Cw`, `RhCw`, `RH8` → RHW1.
    - `Kell` and `KEL` → KEL1. The Kell system contains KEL1, so the system name is read as D, even though `k` / KEL2 alone is C.
    - `Kidd` and `JK` → JK1 and JK2.
    - `Duffy` and `FY` → FY1 and FY2.
    - `anti-X` reads as X, so `anti-D` → RH1 and `anti-A, anti-B` → ABO1, ABO2.
    - Traditional names A, B, AB, A,B, C, c, E, e, K, Jka/Jk(a), Jkb/Jk(b), Fya/Fy(a) and Fyb/Fy(b) map to their markers.
  - **→ recognised, not listed (C).** These are read as markers but are not on the Rule 2 list:
    - ISBT codes of other systems or other antigens (LE1, KEL2, DI1, FY3, ...).
    - Traditional names A1, M, N, S, s, U, P1, k, Kpa/Kpb, Jsa/Jsb, Lua/Lub, Lea/Leb, Dia/Dib, Wra, Xga, Yta/Ytb, Fy3 and Jk3.
    - System names MNS, Lutheran, Lewis, P1PK, Diego, Cartwright/Yt, Xg, Scianna, Dombrock, Colton, LW, Chido/Rodgers, Kx, Gerbich, Cromer, Knops, Indian, Raph, JMH, Globoside, GIL, RHAG, FORS, JR, Langereis and Vel.
    - Tissue, platelet and neutrophil typing: HLA…, HPA…, HNA….
    - ISBT symbols that are also English words (in, do, I, H, P, OK) are left out, so free text cannot match them.
  - **Free text** ("Lewis (LE1)", "ABO/RhD", "anti-A, anti-B and anti-D reagent") is accepted only when at least one token names a marker and every other token is a filler word (system, antigen, typing, reagent, and, ...).
  - **Anything else is refused.** That covers an unknown word ("cancer", "Bombay phenotype"), an empty string or a non-string. The engine throws `DeviceClassificationFactError` (`code: 'VALIDATION'`, HTTP 400 on `POST /device/classify`, an `error` result from AnA's `classify_device`). Before round 2, any unrecognised string was read as a non-listed marker and stated Class C. That included the Annex's own system names, so "ABO" or "RhD" came out C, not D. This was the fail-open direction under DECISIONS.md #1.

**Platform conventions added in the retry (not regulator text):**
- **Closed tables, no open patterns, no nested quantifiers.** Rule 2 markers, Rule 3 points and Rule 4(a) analytes are read by lookup in closed tables. Tissue, platelet and neutrophil typing (HLA/HPA/HNA) is read by a closed grammar checked without a regex (review fix round 4; it was an open character set, so "HLA-ABO" read as typing → C): `HLA` alone, or `HLA-<locus>` with the locus from the closed table in row 22, followed by nothing, a serological number ("B27"), a `W` number ("Bw4") or `*` and an allele of 1–4 groups of 2–4 digits joined by ":" with an optional expression suffix (N, L, S, C, A, Q); `HPA` / `HPA-<1–2 digits>[a|b][w]`; `HNA` / `HNA-<1–2 digits>[a|b|c|d][w]`. Anything else after the prefix is refused, so a listed marker joined on ("HLA-ABO", "HLA-ABO typing", "HLA-A:RhD", "HPA-RHD", "HLA-KELL", "HLA-A*RhD") is never read as typing. The only regexes left are single character classes with one `+` (`/\s+/`, `/[^a-z0-9]+/`, the token splitter), which are linear. Every free-text value is capped at `MAX_FACT_TEXT_LENGTH` = 100 characters and every list at 50 values; longer is refused unread. The round-3 ReDoS (`TISSUE_TYPING = /^(HLA|HPA|HNA)([-:*]?[A-Z0-9*:]+)*$/i`, 2.6 s at 28 characters, exponential) is gone; the test bounds hostile inputs at n = 30 and n = 2000 to < 250 ms per pair of calls (loose, so host load cannot fail it; exponential growth still does).
- **Words run together never hide a listed marker.** A token containing whitespace can only be read as *listed* (D); only a whitespace-free token can read as *not listed* (C). So "HLA and RhD" → D, never "HLA…" typing → C.
- **Unknown keys and malformed values are refused.** `classifyMdr` / `classifyIvdr` read facts against closed key sets (`MDR_FACT_KEYS`, `IVDR_FACT_KEYS`, enforced at compile time by a mapped type). An unknown key ("pacemaker", "cancerScreening"), a non-boolean where a boolean is read ("true", "yes", 1), or a value outside an enum (duration "long") throws `DeviceClassificationFactError` (`code: 'VALIDATION'`, HTTP 400 on POST /device/classify and /device/blueprint; an `error` from AnA's classify_device and build_device_blueprint). The reverted engine ignored unknown keys (classifyIvdr({cancerScreening:true}) → B) and read `selfTesting: "yes"` (and `"false"`) as true. `invasive: false` together with an invasive kind is refused as contradictory. `selfTestAnalyte` without `selfTesting: true` is refused.
- **Default rules are never a verdict on facts nobody gave** (as of review fix round 4).
  - MDR: whenever `invasive: false` was not stated and no kind of invasiveness was given, the result is `class: null`, `missingFacts: [MDR_MISSING_INVASIVE]`, unless a rule already gives III. Rule 8 covers every implant, so every class below III depends on it: `{active: true}` (Rule 13, I), `{activeTherapeutic: true}` (Rule 9, IIa), `{active: true, administersMedicine: true}` (Rule 12, IIa) and `{software: true}` (Rule 11, I) are all not determined, because the same device implanted is III (Rule 8, active implantable). Before fix round 4 this applied only when residual rows alone fired.
  - MDR qualifiers: a fact that qualifies another is read only with it. Given true without it, the class is not determined and `missingFacts` names the fact it qualifies; given true with that fact stated false, it is refused as a contradiction. `energyExchangePotentiallyHazardous` needs `activeTherapeutic` (Rule 9); `administrationPotentiallyHazardous` needs `administersMedicine` (Rules 6, 12) and a device one of those rules reads it for — active (Rule 12) or transient surgically invasive (Rule 6) — or one already at IIb/III for administering medicine (short-term surgically invasive, Rule 7; Rule 8's scope) (row 26, fix round 5); `inhalationEssentialImpactOrLifeThreatening` needs `inhalationMedicinalProduct` (Rule 20); `ionisingRadiation` needs `activeTherapeutic` (Rule 9), `activeDiagnostic` (Rule 10), a transient or short-term surgically invasive device (Rules 6/7), or Rule 8's scope (row 23). Before, `{invasive: false, active: true, ionisingRadiation: true}` — an X-ray/CT generator — came out Class I under Rule 13.
  - IVDR Rule 2: `bloodGrouping: true` with neither `bloodGroupingMarker` nor an explicit `bloodGroupingHighRisk` (true or false) gives `class: null`, `missingFacts: [IVDR_MISSING_RULE2_MARKER]`, unless another rule gives D. Rule 2 is C or D by the marker, and the most common blood-grouping devices type ABO/RhD (row 24). `{bloodGrouping: true, bloodGroupingHighRisk: false}` is the statement that gives C. Before, `{bloodGrouping: true}` was C.
  - IVDR Rule 6: the Class B default is stated only when the facts say each higher-class rule does not apply — `bloodDonationScreening`, `lifeThreateningHighPropagation`, `infectiousLoadLifeThreatening`, `bloodGrouping`, `infectiousOrCancerOrGenetic`, `selfTesting`, each given true or false (`IVDR_RULE6_MISSING`). Before fix round 4 any single fact, even `{companionDiagnostic: false}`, reached Rule 6's B.
- **Contradictions are refused, never resolved one way** (`DeviceClassificationFactError`): MDR `invasive: false` with an invasive kind; a qualifier true with its own fact false. IVDR `bloodGrouping: false` with a marker or with `bloodGroupingHighRisk: true`; `bloodGroupingHighRisk: false` with a listed marker, or `true` with a marker naming none; `companionDiagnostic: false` with `rule3Points` (f); `infectiousOrCancerOrGenetic: false` with any Rule 3 point or `companionDiagnostic: true`.
- **A fact whose rule describes an active device makes the device active** (fix round 5, row 25). `ACTIVE_FACTS` is every fact a rule row reads as describing an active device: `active`, `activeTherapeutic`, `activeDiagnostic`, `activeImplantable`, `closedLoopDiagnosticFunction`, the six software facts, and the Rule 9/10 facts `monitorsVitalParametersImmediateDanger`, `diagnosisPatientInImmediateDanger`, `controlsActiveTherapeuticIIb`, `controlsActiveImplantable`. A rule row and `isActive` must never disagree: a fact that fires an "Active devices …" row but leaves `isActive` false would make an implant carrying it a non-active implant (Rule 8, IIb), not an active implantable (III). A new fact for an active-device indent goes in this list.
- **An absent boolean otherwise reads as false** (the caller states the properties the device has). The exceptions are the facts above. Known limit: `{implantable: true}` without `active` reads as a non-active implant (Rule 8, IIb), the HEAD behaviour pinned by device-blueprint.test.ts and device-readiness-scorecard.test.ts. Other facts given for a device whose rules do not read them (e.g. `contactsCnsOrCentralCirculation` on a body-orifice device) are not refused; the review did not ask for it and the Annex gives them no role there.
