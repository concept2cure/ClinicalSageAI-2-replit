# Stored workflow materialization

The read-only `workflow-source-import.ts` materializer takes the caller's executor and transaction snapshot. It creates no source association, document, approval, signature or reservation. The bridge owner controls preview/creation isolation, creation-time fingerprint comparison, canonical draft writes, reuse and later source verification.

Protocol source scope comes from the actual `protocol_documents.study_design_id` and tenant-owned `cdisc_prm_studies.program_id`, then the existing unique project anchor and sharing policy. Organization-scoped sources remain organization scoped and require an explicit target association reason on creation. A missing or invalid recorded relationship refuses rather than becoming an unbound source. Source access is checked before synopsis or section prose is selected.

Canonical protocol export composition retains synopsis, objectives/endpoints, eligibility, visits/procedures and the full assessment-by-visit matrix, including required/optional cells and notes. The working copy excludes generated source status/signature manifestation prose. Ordinary signed protocol exports retain the existing signature manifestation, with an optional executor keeping all reads on the caller connection.

CSR materialization calls the existing `requireCsrJobAccess` through its approved caller-executor overload. It retains exact persisted section codes, canonical ICH E3 titles, content and verified SHA-256 hashes. A selected parent can expand into its actual saved descendants; absent output remains a gap, with no invented parent text. Missing selected output, hash mismatch or job/output project mismatch refuses. Partial jobs and data placeholders stay partial. A recorded model name is a name-only fact; null remains unrecorded.

Protocol machine origin requires canonical live machine/accepted-machine span proof matching the exact source table/row, offsets and current text hash. A stale proof refuses. A tool's `surface: ana`, an ordinary author assertion or a creator ID does not prove model generation. The deterministic `workflow_import` identity proves a copy operation and does not establish original AI authorship. Unknown origin remains unknown. Source signatures, acceptance and model names establish no qualification or approval for the copy.

Fingerprints use the existing canonical JSON serializer and cover original scope, source selection, relevant source row identity/content, retained origin facts, composition and gaps. Association reasons do not change snapshot identity. CSR selection is normalized and only selected output rows enter its fingerprint; unrelated section output does not stale a selected copy. Reads and ordering use explicit tenant predicates and stable source ordering. No global table lock or separate database connection is introduced.

`materializer-regressions.txt` records 59 passing tests across six files: materializer composition/access plus existing protocol signatures and CSR scope/worker regressions. `materializer-source-final.txt` records the final 16 source tests after adding the deterministic-copy false-machine regression and stable span ordering. Counts overlap. `materializer-lint.txt` has no lint errors and only the existing canonical Markdown renderer complexity warning; no new materializer/guard/compositor helper warning.

The tests execute actual PostgreSQL queries through PGlite, including RLS-absent tenant predicates, private access/revocation, inactive actors, source scope integrity, changed fingerprints, partial output and unchanged originals. Native runtime-role, concurrent snapshot and release-control proofs are owned by the independent bridge reviewer and recorded separately. Source hashes prove retained snapshot identity; they do not prove scientific correctness, source approval or model qualification.
