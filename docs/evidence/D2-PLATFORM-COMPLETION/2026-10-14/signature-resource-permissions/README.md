# Current signature resource permissions after reservation

With `GOVERNANCE_RBAC_ENFORCE=true`, the shared signature ceremony previously evaluated resource permission before the target reservation, using the caller's role snapshot and the shared pool. Its later canonical role check could admit a current reviewer while missing that reviewer's explicit resource deny. A missing grant store could also fall back to code defaults and allow a signature. Conversely, a stale caller viewer role could refuse an actually authorized reviewer.

The ceremony still checks canonical signing authority before comparing credentials. After the domain reservation it checks and holds current signing authority, rereads that role through the unchanged canonical resolver on the same transaction, and evaluates the same canonical grant policy using that transaction client. Resource denial returns 403 `NOT_AUTHORIZED`. Unavailable or malformed grant data returns 503 `SIGNING_PERMISSION_UNVERIFIED`. Both roll back before the domain effect, action ledger or signature persistence. No role/grant defaults, permission scopes, deployment flag defaults or canonical signing-role policy were changed. Independent grant writers are not serialized through COMMIT by this read.

`resolveGrants` and `can` accept optional `{ executor, strict }` options. Strict reads require the actual selected role/action/effect and string-or-null dimensions; missing dimensions are refused rather than becoming wildcard grants. Valid custom action/resource/module/classification strings retain their existing semantics. Ordinary callers retain their existing defaults-only fallback and legacy mapping.

The initial two-file regression run produced 11 genuine failures and 11 passes, without harness failures. The actual PGlite ceremony reproduced all three concrete defects: a current reviewer's resource deny still signed, a stale caller role denied an allowed current reviewer, and a grant table renamed during preparation still signed. After implementation, those 22 tests passed. Expanded checks passed 89 tests; a further missing-dimension case then produced one meaningful failure with 17 passes, and tightening that strict decoder predicate closed it. The final six-file run passed 90 tests with zero failures/skips in 14.38 seconds. It includes canonical single-policy and transaction-authority tests plus protocol and report ceremony neighbours. Stored grants cannot override a current non-signing membership, another organization's deny cannot bleed into the current organization, and flag-off behavior remains covered. Forced lint on all four owned files reports zero errors and warnings, with no baseline or cap changes.

The new ceremony suite uses real PGlite role/grant SQL, the canonical grants migration, and a real transactional domain-effect table. Credential verification, separation of duties, and ledger/signature persistence are recorders. This work makes no native PostgreSQL RLS/concurrency, production credential/provider, clinical/scientific, agency, or complete regulated-platform qualification claim. The earlier native authority phase remains separate, with its existing manifest/source pins unchanged.

`manifest.json` pins twelve relevant source/test/policy/migration files and the raw/filed logs. `pre-fix-source-pins.json` records the exact two production sources that produced the baseline red. Complete raw logs remain under their listed `/tmp` paths. Filed text logs remove only trailing blank lines and retain one final newline. The final command runs the six precise test paths in `testFileRecords` through `vitest.config.ts`; Node v22.22.0 used a 4 GB heap. No compiler, index, commit, provider/network or native fixture mutation was performed in this workstream.
