router, single PGlite database, canonical migrations and source builders. The
registered `_authoring-assembly-section-source-cases.ts` cases reuse that host
through its existing fixture interface pattern. No second app/database, provider,
retrieval implementation or editor is introduced.

Four relevance cases cover Data Room and Vault with a persisted title-only
template and the existing PER component's guidance-only precision term. Long
generic front matter competes with a later synthetic scientific marker. The
title cases also normalize `a.3` selection and preserve a differently named saved
heading, requiring relevance to use the canonical template title. They check
preview writes nothing, the chosen excerpt is later and bounded, source/excerpt
hashes match exact text, replay returns exactly that recorded slice, and commit
plus its assembly audit retain the same manifest while authored text remains
unchanged. No source prose is copied into the plan or empty template section.

matching terms. Three structure controls require missing selected rows,
normalized duplicate template codes and ambiguous saved codes to fail before
reading any selected Data Room source. The existing route suite continues to own
access/freshness/rollback checks and exact-span replay despite a later query.
