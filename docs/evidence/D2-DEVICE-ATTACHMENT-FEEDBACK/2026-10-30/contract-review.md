Do not replace this with a generic success label, invent another message interpreter, claim durable dossier association, or add a blind Retry/automatic resubmission path. A new deliberate selection may reuse the existing hook, which already clears its note when beginning a real batch. Missing-project behavior must remain honest, without a silently dead picker.
3. **Make the existing chooser keyboard-operable.** A native Choose files button can trigger the existing hidden input while retaining drag/drop and current mouse activation. Preserve input reset and selected File identity. If the drop container retains a click handler, stop button/input propagation as needed so one keyboard/pointer gesture does not trigger a second picker click. 4. **Prevent reentrant batches before repaint.** Use a synchronous per-visit busy latch as well as rendered pending/disabled state. The latch must be reset in a finally path. A second change/drop/click before React renders the disabled controls must not issue another POST or replace the first batch's outcome. 5. **Keep one mounted owner across ordinary tab changes.** The attachment orchestration must remain mounted while Document/Attachments/Activity visibility changes within the same open drawer visit. Reuse `useAuthoringReadSession(useAuthUser())` (or a justified equivalent canonical guard) plus `captureShellProjectGuard`/`useShellProject` in the established keyed-context pattern. An active/unmount flag and captured visit identity must fence start/publication after close, unmount, changed context and A-B-A. A new owner must start with fresh pending/note state. The old continuation must not append metadata into a newly hydrated local store. Store/public hook/server/API changes are not needed.
7. **Preserve ordinary same-account refresh.** Ownership depends on account/session revision, not the raw bearer string. A successful ordinary token refresh must keep the current upload, feedback and local publication alive. Pending session adoption and true session/account replacement must retire it. A shell metadata update for the same project should likewise preserve the visit, while a real shell-project change or A-B-A retires it even if React batches away an intermediate render.
8. **Keep current upload truth and scope.** Preserve exact original ordered File objects, per-batch confirmed indexes (not filename or File-object Sets), valid HTTP201 and HTTP200 reupload outcomes, auth/body/progress/order, no automatic retry, receipt validation and local no-audit behavior. In-flight network work may still complete for the original governed program; no network abort, rollback or stopping the shared hook's remaining queued requests is introduced or claimed. ## Fixture and implementation pitfalls

`authService.setToken` always increments authRevision and emits login. Calling it again for the same actor models a replacement session, not an ordinary bearer refresh. The refresh positive should use the actual refresh flow or a faithful revision-preserving fixture that exercises canonical guard behavior; `_doRefreshToken` updates tokens and emits token_refresh without incrementing the revision. Never mock the lifetime guard to always true for ownership proof.

Session ownership tests may use a null provider fixture while the auth singleton remains current; the existing guard's revision/account snapshot is still the authority. Do not introduce an authentication bypass or redefine backend admission to make fixture setup easier. Restore actual auth/shell state after each controlled test.

A mutable array-backed FileList seam is a controlled consumer vector, not native-browser liveness proof. Native keyboard/file-picker/drop interaction and narrow-screen wrapping can be verified separately with a synthetic actual-component browser harness, without calling that authenticated client acceptance. Synthetic receipts do not prove persisted bytes, a signed ceremony or live government transport.
