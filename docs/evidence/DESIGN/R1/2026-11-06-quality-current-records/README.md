## What already exists

Pre-implementation inventory at `f6127e7223` (F1 follow-up to the existing R1/S2 Quality integration).

Existing `server/export/authoring-section-content.ts`, `inline-marks-to-text.ts` and shared plain-text/HTML helpers already supply type-aware projection. Reuse these within the current renderer and UI/PDF tests; sealed native snapshots stay exact.
- `server/services/report-os/project-access.ts` already rechecks authored grants per saved report, but its other native register grants survive across reports in one history/bundle read. Existing QMP deletion and change-control soft deletion can remove eligibility without changing actor/project/workspace anchors. Reuse the current native collector with per-report admission maps; existing saved-report SQL tests cover actor, exact-object, workspace and historical evidence behavior.
- `server/services/report-os/research-compliance-report-providers.ts` fences each project's collection independently and rechecks project access after merging them. It does not revisit unique earlier-project facts after later projects load. Reuse the same collector for a final per-project identity/content comparison before returning a combined report; existing provider/engine tests pin fail-closed output and persistence order.
- The existing immutable collector, project catalogue, shared editor and report pipeline remain their owners. No new screen, route, service subsystem, table, editor, model or dependency is needed.
- Searches included native producers, task/source readers, canonical schema/lifecycle, existing tests and `git log --all --diff-filter=D` over tasking/CAPA. The repository is not shallow; no deleted replacement was found. Quality register and Project UI files remain held by their current owners and are excluded.

## Repair contract

1. CAPA/action reconciliation must verify the current tenant-owned record and existing project/actor admission under its existing lock and transaction. Current lifecycle/date and known numeric assignee must justify the active task or no open task and its exact completed/cancelled outcome. The old changed-assignee guard did not cover stale numeric owners with no task or an unchanged task assignee; these cases also need current-record verification. Stale or denied work preserves existing tasks and audit atomically, including delayed active plans after closure. Preserve free-text owner policy and all held QMS/training behavior.
2. Catalogue admission must keep inaccessible records private while refusing a readable native snapshot that changed during capture/admission. A normal refresh can reconcile the current immutable snapshot; a false empty success is not acceptable.
3. Report UI/PDF must preserve clinical comparison operators, literal tag-shaped prose, entity meaning and unresolved suggestion markers through the existing canonical text projection. Full sealed payload and existing status qualifiers remain unchanged.
4. Each saved report must recheck its native grants even inside one history/export batch. Reuse canonical current collector admission and preserve inside-report deduplication, executor/actor binding, historical text and fail-closed report responses.
5. Combined Quality report collection must refuse an observed change in any previously collected project before returning its result. Preserve native scopes, exact snapshots, partial status, existing limits and final access fence. This adds a bounded freshness check, without asserting global atomic snapshot isolation or completeness.

## Boundaries and existing handoffs

- The combined-collection check detects observed drift; it is not a database-wide atomic snapshot or a completeness/assurance claim.
- PGlite task tests execute ownership and rollback SQL but use seams for advisory locking and project/actor admission. The real runtime proof verifies those current admissions sequentially; it is not a stress test of every concurrent interleaving.
- CAPA/action lifecycle checks do not change held QMS periodic-review/training snapshot semantics. Those remain with their current owners.
- Quality register project filtering/QP3, the Project core-work Quality door and the observed Quality mobile tab overflow remain in their existing Quality/Project UI holds. Their files were not edited. This slice does not claim CMC/RBM/Biostatistics parity.
