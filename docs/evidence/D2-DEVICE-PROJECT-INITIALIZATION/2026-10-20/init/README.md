## What already exists

The registry and filing catalog already identify these eight application records,
and the existing device authoring groups/project blueprints/editor template library
already supply their exact working outlines. Those groups remain preparation aids
with unreviewed applicability; they are not complete agency forms or requirement lists.

`Projects.tsx` already renders one registry-driven wizard and records its selection.
`project-intake.ts`, `document-class.ts`, `rule-pack-lookup.ts`,
`scaffold-project-documents.ts` and `governed-document-binding.ts` already own
product validation, exact document class/pack lookup, transactional creation and
later editor binding. `market-support.ts` already owns the shared picker/create
verdict. This increment reaches those paths using the shared eight-row application
contract; it introduces no second wizard, editor, class vocabulary or scaffolder.

`required-sections.ts` already supplies CTD requirements and a labelled medicinal
fallback to compile, status, validation and Vault coverage. That fallback was
reachable for the newly admitted regional device classes. Existing eCTD routes
already resolve real tenant-scoped program anchors; their prologues now refuse
these preparation types before requirements, sequence, rendering, write or external
validator-import work. Vault reuses its existing not-applicable outcome.

Code/route/service/schema/AnA searches and deleted-history review are recorded in
the implementation contract. No separate regional governed project pipeline was
found to restore. Documentary filing classes remain document-only.
