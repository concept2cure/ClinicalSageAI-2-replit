## Design

Keep the existing hook API and transport. Bind a batch to the initiating project visit and canonical session revision. Stop unsent files and suppress callbacks, notes and actionable outcomes when that owner retires; do not claim an already dispatched write was undone. Allow ordinary admitted token refresh within the same session. Prevent same-turn duplicate dispatch with a synchronous batch token; an old completion cannot release a newer batch.

For HTTP failures, reuse `mutationUnconfirmed` so gateway failures remain unknown and tell the person to reload/check. Preserve definite request refusals and their sanitized reasons. No automatic retry, server write, new surface, schema or dependency is introduced.

Complete the existing MDX caller by showing the shared outcome/busy state, matching confirmed files by their request index rather than their names, and binding the upload visit to the open dossier section. Extend the hook with an optional visit key for this caller; program ID remains the actual request project. Closing or changing sections retires old callbacks/results. The existing attachment store remains a local presentation list, with no fabricated audit entry.

## Implemented behavior and review

`vaultUploadVisit.ts` holds only the existing uploader's local visit/batch lifetime; canonical session revision, account and credential admission remain with `authService` and `useAuthoringReadSession`. Project/section changes, session/account replacement, credential drift and unmount retire callbacks and unsent files. Each attempt has a synchronous ticket, and an old completion cannot release a replacement batch. A retired caller receives no actionable recorded IDs. A write already dispatched may still finish on the server; retirement does not claim to undo it.

The existing Vault project-body key now also names its canonical session, withdrawing the previous account's staged files and private metadata. Normal admitted bearer refresh preserves the selected File object and field edits. MDX shows the shared outcome in permanent live regions, guards busy dispatch and associates only confirmed request indexes with the existing local attachment list. It does not fabricate persisted attachment or audit records.

Caller qualification enforced MDX's existing shared-failure contract: attachment errors now use the existing inline `ErrorState` component, with explicit dismissal through `clearNote` and no request retry. The busy/success live region remains present. Twelve obsolete full auth-module mocks were completed through partial imports so the canonical header/session helpers remain available at render. One existing De Novo fixture now waits for its actual field-read request, as its PMA sibling already does, rather than assuming the heading means the request has started; its route/pathway assertions are retained.

Uncertain HTTP outcomes use the existing mutation policy, with upload body-size/type refusals retained as definite refusals. Explicit `OUTCOME_UNKNOWN` takes precedence. Gateway fallback copy no longer calls the unknown write a refusal.

Independent source review reported no unresolved blockers in these scoped changes. Archive findings, native evidence and the transaction/delivery boundary are recorded in [the D5 follow-up](../../D5/2026-10-30-vault-final-access/README.md).
