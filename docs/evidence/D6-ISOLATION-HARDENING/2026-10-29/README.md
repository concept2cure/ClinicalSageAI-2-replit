## 1. A citation cites only its own organization's document (P-66)

**Open:** as tenant B's runtime session, `INSERT` with source = B's document and evidence = A's document succeeded (red.txt §2), though B cannot even see A's document. The row is B's; A's purge deleted it by cascade (D6-TENANT-EXPORT-GAPS, "Reported, not fixed" 1).

**Changed** (`migrations/20260911_vault_evidence_citations.sql`, amended in place, dated header):

- INSERT's WITH CHECK, and now UPDATE's: the source is writable (`can_write_program`), the evidence readable (`can_access_program`), and `core.get_program_org_id(evidence) = core.get_program_org_id(source)`. Organization, not access: a delegate organization that may read a sponsor's program (`identity.org_relationships`) still cannot cite the sponsor's document. SELECT and DELETE stay on the source, the row's owner.
- The four policies are replaced only when the stored policy (`pg_policy`: command and the clauses each end needs, read by `pg_get_expr`) is not this shape. On the HEAD database the first deploy replaced INSERT and UPDATE and left SELECT and DELETE (same oids); the second deploy replaced nothing (green.txt §2).
- Fails closed if `core.get_program_org_id` is missing where `core.can_access_program` exists, rather than leaving the source-only check.

**The application writer** (`persistEvidenceCitations`) already refuses: it writes evidence = source = the cited document, and only where that document is the caller's organization's. Now pinned: run as a superuser (no policy in the way), it files nothing for A's document under B's uuid, and one row for B's own (M5 removes its predicate and is caught). There is no other writer.

Rows written before this keep their place: none existed in the lane; production is not known here (query in "Reported, not fixed").

## 2. The Vault child tables FORCE row-level security (P-66)

**Open:** a NOSUPERUSER NOBYPASSRLS owner (the shape of a managed Postgres migration role), in tenant A's scope, read tenant B's row in five tables: `document_chunks`, `document_catalog`, `document_read_receipts`, `evidence_citations`, `document_archives` (red.txt §2). `vault.documents` was already FORCEd.

**Found on the way, and fixed with it:** the purge's Vault door deletes as the owner and relied on the owner skipping row security. Since `vault.documents` was FORCEd on 2026-10-14, on any database whose owner is not a superuser the door returned **0 versions**, deleted no version, no chunk and nothing that cascades from a version, and only the archive went (red.txt §2, door probe). CI could not see it: its owner is a superuser. FORCE on the children would have taken the archive too.

**Changed:**

- FORCE, set only where not yet set, in each table's creating file: `20260905_document_catalog.sql` (catalog, receipts), `20260905b_vault_document_chunks.sql` (chunks), `20260911_…` (citations), `20260926_…` (archives). Each amended in place with a dated note.
- The door (`20260926_…`, amended in place): it now sets `app.current_org_id` to the purged organization's uuid, locally, for its three DELETEs, and puts the caller's value back before it returns. The Vault policies then admit that organization's rows and no other's, so the predicate is no longer the only thing between the door and another tenant. The preconditions, the predicate and the return are unchanged. `to_jsonb(o)->>'uuid'`, so the PGlite fixture without a uuid column runs as before.

**Owner probe, after** (green.txt §3): the same owner reads A's six rows and none of B's; the door, owned by that role, returns 2 versions, A has nothing left in any Vault table, B keeps all six, and the caller's scope is back as it was.

Nothing else writes these tables as the owner: no migration in the set writes them; the one definer function that does is the door; the runtime refuses to boot as the owner. Foreign-key cascades and SET NULL run without FORCE (PostgreSQL's referential actions), so the cascade from a version to its catalog, receipts and citations is unaffected.

- **The v2 migration** inserts each source under its v2 identity with `previous_version_id` = its v1 row, retires the v1 row (`is_current` TRUE → FALSE, the one change the capture guard admits), and asserts: row count and identity (title, version, checksum, artifact, text, payload sha) for v2 plus the v1 sources withdrawn before it ran; no v1 source still current; no current public reference carrying a fit. A v1 source withdrawn before v2 ran stays withdrawn and gains no successor. v1 is byte for byte as applied and re-runs before it.

A computed fit, if wanted, is new capability and a founder decision.

## 5. The Client Review Room admits the project (P-61 item 5)

**Open:** a request naming program A got the organization's shared tasks for every program, under `meta.programId: A`; a foreign or missing `programId` or `project_id` was answered 200 (red.txt §3).

**Changed** (`server/routes/mdx-client-review.ts`, `admitRoom`):

- `programId` → `admitProject` before anything is read: 404 "Project not found" for another organization's, a missing or a deleted project; 503 when the check cannot run.

- There is no write in this route, so there is nothing for `requireEditorAccess` to gate.

The hook's comments (`useClientReview.ts`) said `programId` was only echoed; corrected. No client behaviour changed.
