## An edit that moves nothing writes no row

The same PUT body sent twice. The second changes nothing, so §11.10(e) has
nothing to record, and a ledger of no-ops would bury the real edits:

```
a no-op edit:                 HTTP 200   update rows before=1 after=1
an edit that moves one field: HTTP 200   update rows now=2
```

The second attempt in that run was `{"status":"validated"}` and came back
**409** — `validated` is a governed signed state, reachable only through the
signing ceremony, not an ordinary PUT. That is the ungoverned-signed-state
refusal from slice 05 holding; the one-field edit above used `title`.
