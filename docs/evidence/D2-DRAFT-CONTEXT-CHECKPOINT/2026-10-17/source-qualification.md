# Source context authority checkpoint

The source-owned implementation and tests are frozen at the hashes in `source-final-manifest.json`. The final focused run passed **82 cases in two files**: 42 existing producer cases and 40 context-authority cases. All fifteen source bindings stayed unchanged during the run. ESLint reports zero errors and zero warnings across the module and both fixtures. These counts overlap larger integration cohorts.

`loadDraftProjectSources` now freezes each selected source/span, the source array and the returned loaded context, and registers only a successfully rechecked context in a private `WeakMap`. Public equality of its fields cannot manufacture issuer authority. The registry exposes no token, executor, callback or added source body through prompt receipts or audit metadata.

`assertDraftSourceContextCurrent(context, identity)` first distinguishes ordinary absent/empty-unassessed drafting from genuine registered loaded contexts. For a loaded context it copies the consumer's organization/user/project identity before any await and matches it to the original loader identity. Canonical decimal actor IDs and UUID casing are accepted; numeric project identifiers use the existing parser. The original `projectRef ?? projectId` preference is preserved. A different project alias cannot replace an original UUID reference through a new lookup. Copied, JSON-roundtripped, cloned or fabricated loaded contexts and mismatched consumers refuse before current source reads.

The loader's original final source verification is one shared closure used at loader return and every later checkpoint. It privately rereads each actual current extraction through the canonical actor facade, compares the original source/extraction/availability/disposition state, recomputes the full extraction and exact original UTF-16 span identities using the existing factory, and rechecks current actor/program scope. It neither replaces the selected excerpt nor chooses another window. The prompt and audit helpers share the same registry validator before describing loaded evidence.

Controls cover all frozen nesting levels; copied and malformed contexts; numeric/string/UUID identity normalization and mismatch; immutable consumer input across a source await; repeated current checks; same-length extraction changes inside/outside the excerpt; withdrawal, current-version and retained-source caveat changes; actor/program revocation; an unchanged `keep_data` source; a valid non-opening Japanese/astral Unicode span; and a lossy UTF-8 surrogate alias that must refuse. Audit output retains hashes and copied coordinates without extraction bodies. Existing producer controls remain green, including bounded selection and loader-return rechecks.

The actual loader, issuer, identity factory, window selector and checkpoint closure run in these tests. Catalog admission and current actor/program reads are explicit synthetic authority seams; this is not a database policy, RLS, provider or runtime-load qualification. The service and gateway owners separately exercise entry, dispatch and response boundaries. Issuer membership is process-local, and checks are checkpoints: they cannot recall text already sent or continuously revoke an in-flight provider. No delivery/model-use, scientific approval or agency acceptance claim is made.
