# Gateway current-source checkpoint qualification

The trusted optional `GatewayRequest.beforeDispatch` callback is captured and validated synchronously in `route`, before placement or policy awaits. Primary and fallback retry closures carry that captured reference into the existing `executeProvider` path. After acquiring the existing outbound semaphore permit, this path awaits the callback, checks cancellation again and then invokes the unchanged provider dispatch. Ordinary requests omit the callback and add no checkpoint await.

Malformed callback values, throwing accessors and synchronous/asynchronous callback failures produce the same safe `GatewayPolicyError`, with `code: SOURCE_CONTEXT_UNAVAILABLE`; underlying access/SQL messages and causes are not propagated. Existing terminal-error handling prevents retry, fallback and provider-failure accounting for that refusal. The existing semaphore `finally` releases the permit on success, refusal or cancellation. Provider implementations, SDK configuration, model rows and qualification policy are unchanged. The qualification-only `evaluateModel` entry retains its existing path; selected-source drafting enters through `route`.

The final six-file regression passed all 45 tests, including 16 new checkpoint controls. New controls exercise the real route, admission, placement, limiter, retries and fallback selection; only network dispatch is replaced. They cover queued revocation, callback replacement after route entry, terminal safe errors, malformed values/getters, primary retry, fallback retry, cancellation while a guard awaits, released permits and unaffected no-source/current-source work. Existing SDK retry ownership tests replace fetch in process and make no network requests.

The final counterfactual config replaces only the guard invocation with a resolved promise at module load. Five selected behavioral controls then fail, while the production files remain untouched. This verifies that the controls detect omission of the final check, rather than merely detecting an absent interface. The first counterfactual attempt was interrupted after configuration merging accidentally concatenated the broader base include patterns; its log and config are retained and do not qualify this change. The corrected final config overrides include explicitly and runs only the owned suite.

Before/after bindings match for all five recorded gateway dependencies. ESLint reports zero errors; the new test and types file have zero warnings, and the gateway retains the same 25 warnings with identical rule counts as the canonical baseline. Counts overlap the lead's integrated cohorts and must not be added together.

This provides a source-currentness checkpoint immediately before each gateway dispatch attempt. It does not lock source stores across network waits, recall transmitted text, continuously revoke an in-flight call, prove provider delivery/use or establish scientific or agency acceptance. The callback remains an internal trusted code seam. Final integration, whole-tree checks and direct canonical publication belong to the lead.
