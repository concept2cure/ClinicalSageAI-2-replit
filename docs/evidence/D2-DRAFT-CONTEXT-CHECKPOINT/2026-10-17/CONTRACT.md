# D2: genuine selected-source contexts and current generation checkpoints

17 October 2026. Lead-approved contract under the user's continuing instruction to improve the existing Data Room/AnA and publish incrementally, directly to `concept2cure-v2`. Baseline: `d6a33d3a4a09e08a28d9a3b6047e30fe3a2532d1`. This moves launch D2 within existing Vault/Authoring and the existing provider gateway; it does not close D2 or add a product surface, model, provider, dependency, migration or filing route.

## Demonstrated defects and outcome

The HTTP `/api/claude/batch` route spreads caller request items into internal drafting requests, preserving arbitrary `sourceContext`. The drafting service labels that text as server-loaded evidence without admission. Separately, AnA loads every section's sources before the bounded-concurrency batch starts. Later sections can wait while an earlier model call runs; their retained source context is not rechecked. The gateway also awaits policy, placement and outbound capacity. Existing V2 save/export verification eventually refuses changed evidence but cannot protect generation already performed or its successful receipt.

Close both defects through one canonical context authority in `ana/draft-project-sources.ts`. Retain the existing V2 original/extraction/excerpt identities, absolute UTF-16 spans, budgets, current actor/program/private-parent checks and honest historical save/export semantics.

## Shared interface and invariants

1. `loadDraftProjectSources` privately registers every successful loaded context in a module-private `WeakMap`. Its stored binding contains the already-pinned actor/project identity, immutable source snapshots and a closure using the canonical actor facade, exact identity factory, actor revalidation and current program check. Freeze the returned context, source array, each source and each span before exposure. No registration token, executor, callback or raw additional text enters public receipts or persisted provenance. Registry entries are process-local and become collectible with the context.
2. Export `assertDraftSourceContextCurrent(context, identity): Promise<void>`. `identity` has the drafting request's `organizationId`, `userId` and `projectId` (string/number/undefined as already supported by that service). Undefined or a genuinely empty `unassessed` context continues ordinary drafting. A purported loaded context, malformed status or nonempty unassessed context must be a genuine registered object; a plain object, JSON roundtrip, object spread or cloned receipt cannot create authority. Match current consumer identity to the original pinned organization/user/project; never borrow the original actor's authority for another consumer. Snapshot the identity before awaits.
3. Current-context verification reuses the loader's existing source-state comparison and final exact-text recheck, not a second catalog reader or digest implementation. Check every source's actual current body privately, retained-source availability/disposition/extraction caveats, full extraction/exact span, and current actor/program scope. Recompute from current text without silently replacing the original excerpt or reselecting a different window. Preserve valid non-opening Unicode spans and eligible retained `keep_data` sources. No new SQL or source-body API is needed.
4. Pure source prompt/audit helpers must not label an unregistered loaded context as server-issued. Share the registry membership validation rather than inventing another trust marker. Existing text/metadata minimization remains: public source receipts contain identities/caveats and no extraction body; existing bounded figure/claim diagnostics remain unchanged.

## Draft service and outbound gateway

5. `AnaDocumentDraftingService.draftDocument` snapshots caller-owned request identity, source-context reference and declared project context before its first await. It verifies a selected-source context before building/sending source-bearing messages and again after a response, before returning content. A failure returns through existing safe per-section failure handling; it does not discard successful siblings or invent a saved document. Keep ordinary no-source drafting unchanged.
6. Selected-source generation currently enters through the nonstreaming batch tool without agentic model tools. Refuse selected-source streaming (`onStream`) and selected-source agentic tools (`enableTools`) before gateway handoff until their multiple-release/multiple-SDK-call boundaries are separately qualified. Ordinary no-source streaming/tools retain their existing paths. This closes the possibility of emitting content before the final check; it does not remove a currently reachable trusted-source streaming caller.
7. Add one optional trusted-server callback on `GatewayRequest`: `beforeDispatch?: () => Promise<void>`. It is not a wire/API input, metadata, authority token or serialized receipt. The service supplies a closure over the original registered context and pinned identity for selected-source generation. No-source requests omit it. HTTP callers cannot supply functions or a loaded context through this field.
8. The gateway captures and validates the callback before its first await, and passes that captured reference to the canonical `executeProvider` path for the primary and every fallback/retry. Invoke it inside the outbound semaphore after capacity is acquired and immediately before `dispatchProvider`; then recheck cancellation before starting dispatch. Preserve all placement, classification, policy, model qualification, circuit breaker and retry controls. Callback failure becomes a fixed safe `GatewayPolicyError`: terminal, no retry/fallback of the refusal, no provider-failure accounting, and the semaphore permit is released. Do not expose the underlying SQL/access error text. No new provider implementation or SDK credential work is authorized or needed.
9. These are checkpoint guarantees. They do not lock a database across network waits, recall text already sent, continuously revoke an in-flight provider, prove delivery/model use, or establish scientific qualification or agency acceptance. A source change during a provider wait can suppress returned content, while the attempted generation remains an honest gateway event. Internal provider SDK behavior is unchanged; selected-source agentic loops and streaming are refused as above. The callback is an internal trusted code seam, not a public cryptographic capability.

## HTTP boundary

10. `/api/claude/batch` refuses request items carrying the reserved internal `sourceContext` property with HTTP 400 and a fixed actionable message before service invocation or turn recording. Clients continue ordinary drafting and select project evidence through the existing admitted AnA tool. Do not accept a body-supplied loaded-context assertion, strip it silently into a claimed evidence-based success, or broaden unrelated route inputs.
