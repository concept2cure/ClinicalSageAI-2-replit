# Legacy source receipt integrity implementation

The owned implementation is [read-receipts.ts](../../../../server/services/ana/read-receipts.ts), [source-read-receipt.ts](../../../../server/services/ana/source-read-receipt.ts), and their two focused receipt test files. It preserves existing byte-bound receipt storage and aggregate catalog coverage. No migration, table, production dependency or provider invocation was added.

`deferReadReceipt` synchronously takes a private, frozen source/payload snapshot. The snapshot pins identified organization/user/program/document, original record hash, exact complete extraction SHA, actual UTF-16 length/window and optional server thread. Bounds and mirrored receipt identity must agree. The handler result SHA is computed internally. Later caller/deferred-object mutation cannot change the pinned snapshot.

`guardReadResultsForHandoff(original,budgeted,deferred,{signal})` checks unchanged source candidates at the last controlled host handoff. It freshly admits the actor through `admitAnaSourceReadScope` and loads the exact current source through the canonical primitive on the same transaction client. Changed extraction/source, lost private access and unknown amended payloads become a safe no-source result. Canonical budget/cancel replacements remain meaningful. Late cancellation withdraws all source-candidate results, including earlier transformed entries. The guard creates no receipt and ends its connection before model egress.

`settleReadReceipts(original,guarded,deferred,undefined,{signal,onSourceRefused})` preserves exact original/deferred/budgeted string equality and always clears the pending round. Its default writer independently repeats admission/source/payload validation inside a short READ COMMITTED transaction. It takes the existing disposition advisory lock, catalog SHARE, document SHARE and canonical actor/project reservations, using `write:false` to preserve read authority. `INSERT RETURNING` must return one exact legacy row before success. Failure rolls back/skips the receipt. Cancellation is checked before protected work, INSERT and COMMIT; an actual commit observed before later cancellation remains a committed row/count.

An observed actor/source verification failure during insertion is normalized to `SourceReadSnapshotError`. The optional `onSourceRefused(toolUseId)` hook lets the hosts withdraw admitted source payloads from this round rather than submit the earlier successful handoff snapshot. After the typed callback, settlement stops remaining receipt-write attempts; an earlier actual commit remains counted. Canonical `withdrawSourceReadResult` emits `sourceContext:not_admitted` and `legacyReceiptOutcome:unconfirmed`; it never asserts `receiptRecorded:false` or invents rollback. Ordinary lock/INSERT/COMMIT transport or receipt-policy errors, including SQL42501 insertion denial and unverified persistence results, remain write failures and continue other authorized attempts. They do not turn a permitted read into a source-access denial.

Persisted rows remain **aggregate, original-byte-bound host-budget-admitted legacy span history**. The transient extraction/actor checks do not create durable extraction-specific, current-turn or provider-served coverage. A predicted read-window coverage count remains prospective. No gateway request/response identity is fabricated. The handoff guard covers new pending source context, not every previously accumulated conversation/memory message.

The existing receipt INSERT RLS policy still uses `core.can_write_program`. Viewer/custom-role text reads retain their canonical permissions, while their receipt insertion may fail under the exact deployed role/policy. This implementation does not widen that policy or claim viewer receipt durability. The local unit positive uses an explicitly mocked successful INSERT.

The global short catalog/document SHARE reservations fence arbitrary extraction/successor writes through receipt commit. They introduce contention; no production throughput claim is made. No database reservation spans a model/provider await. Real role/concurrency evidence is owned by the independent reviewer and must be assessed separately from the sequential mocks here.

## Evidence

- [Fail-first log](RECEIPTS_RED.txt): nine negative cases failed against the earlier implementation, demonstrating mutable source snapshots and accepted receipts after same-length extraction, private revocation, source movement/hash/disposition/currentness, altered window and invalid bounds.
- [Settlement-refusal fail-first log](RECEIPTS_SETTLEMENT_REFUSAL_RED.txt): two observed failures in typed refusal notification/normalization, with an ordinary SQL42501 insertion-permission control passing. The independent actual executor also preserved the private-text handoff failure before host wiring was fixed.
- [Multi-read fail-first log](RECEIPTS_MULTI_READ_RED.txt): a three-read typed-refusal case showed the third write was incorrectly attempted after known source refusal, while the ordinary SQL42501 continuation control passed. The fix preserves the first successful count, refuses the second, stops the third and clears the map.
- [Focused green log](RECEIPTS_GREEN.txt): 44/44 tests across the existing receipt suite and new snapshot/handoff suite on Node 22, including actual writer-helper mocks, exact payload/window comparison, verified persistence failure, cancellation before work and before/after COMMIT, transformed-result withdrawal, typed settlement source withdrawal, multi-read stopping, ordinary write-failure continuation controls, empty/clear behavior and truthful read disclosure.
- [Selected TypeScript log](RECEIPTS_TYPECHECK.txt): four owned roots plus repository ambient/imported sources, zero selected diagnostics. This is not a whole-repository semantic or build check.
- [Scoped lint log](RECEIPTS_LINT.txt): zero errors/warnings for the four owned roots after splitting validation and handoff responsibilities.

The old registered-read tests keep the real snapshot/bounds/freezing implementation; only their synthetic stored-source verifier/writer uses the existing shared in-memory Vault harness. The new snapshot suite runs the actual canonical guard/writer with mocked records, admission and transaction I/O, not a live database/provider. Separate host and PostgreSQL evidence is required for broader serving/role claims.

Reproduce with Node 22 and `node_modules/vitest/vitest.mjs run server/services/ana/__tests__/read-receipt-snapshots.test.ts server/services/ana/__tests__/read-receipts.test.ts --config vitest.config.ts` from the repository root. Selected TypeScript uses the earlier scientific-catalog `owned-target-typecheck.cjs` runner with these four source/test targets; lint uses the installed ESLint CLI on those same targets.
