## Outcome

AnA's document discovery, source read, text/semantic/passage search, selected Vault drafting sources and file recall must use the identified current actor's actual project access. An open project stays in that project. With no project open, discovery covers the actor's accessible projects, not every project in the organization. Viewers/custom roles retain the reads granted by the canonical sharing policy; read admission never grants governed-write authority. Exact source organization, live parent, unique project/program anchor, currentness and disposition remain source gates.

Source reads that produce deferred span receipts pin the exact server-loaded extraction and source. Changed source, private-project revocation, inactive actor, altered payload or cancellation cannot earn a new legacy receipt. These are still existing aggregate byte-bound host-admission records, not durable extraction-specific/current-actor/provider-served proof. Full V2 ranges/delivery checkpoints and save/export changes are a separate increment.

## Canonical read admission

The authority owner freezes `admitAnaSourceReadScope(q,input)` in the AnA source subsystem. Input is server-resolved `{organizationId:number,userId:number,projectId?:number|null,projectRef?:string|null,requestedProgramId?:string|null}`. Output is server-owned `{organizationId,userId,role,projectId:number|null,programId:string|null,accessibleProgramIds:readonly string[],actorFiltered:true}`. Reject malformed/contradictory identifiers and missing actors; never turn an invalid explicit project into an organization-wide scope.

Extract/reuse current active actor-role lookup from `admitAnaProjectScope` and reuse that project admission plus `getAccessibleReportProjectIds`/`canAccessReportProject`. Do not copy sharing rules or invent a reader role set. The same executor performs actor, anchor and protected source queries. Pooled interactive wrappers stamp matching tenant context and the current persisted role. A stale request/ALS role cannot substitute for membership. Resolve any organization UUID/int pair from server records where retrieval requires it.

For organization-wide discovery, establish anchor uniqueness over **all** same-org anchors before intersecting canonical accessible project IDs. An accessible duplicate must not launder a private duplicate. Unanchored or ambiguous program sources are excluded from evaluated discovery and explicitly refused when requested; unexpected policy/identity/SQL failure is unavailable, not empty. Allowed programs are enforced in SQL **before counts, ranking, window totals and LIMIT**, and metadata/returned rows are checked against exact scope. Never fetch an organization-wide top-N and filter it into an allegedly complete actor page afterward.

Pin the initial server scope. Re-admit after asynchronous embedding/retrieval and before returning source content; if the relevant scope changes, return a named unavailable/refusal instead of stale hits, counts or access. These are bounded point-in-time checks. No database lock is held across provider calls, and no continuous or atomic remote-egress revocation guarantee is claimed.

## Exact snapshot guard for existing receipts

The receipt owner freezes a server-only source snapshot with `{organizationId,userId,programId,documentId,contentHash,extractedTextSha256,totalChars,span:{start,end}}`, plus serving-context/thread identity as available. Actor/project/source values come from admitted context and exact stored extraction; model/body/result metadata cannot attest to itself. Safe integer UTF-16 bounds and actual text/hash/quote length are checked. Take a private snapshot synchronously when deferring so later object mutation cannot change the admitted source or payload.

`verifyAnaSourceSnapshot(q,snapshot)` reuses canonical read admission and exact current source loading. It validates recorded organization/program/document/hash, current eligible source, exact nonblank extraction SHA/length and span. The canonical receipt writer repeats this check inside its short transaction before inserting the existing row, using an explicit source/catalog reservation order if needed to fence source changes through commit. It preserves viewer read authority and adds no governance decision. Missing/changed source or write failure yields no accepted count.

Host-budget settlement still requires exact unchanged original/returned strings and clears each round's deferred receipts. Preserve replacement/cancellation behavior and whole-or-nothing payloads. Revalidate source snapshots at the host handoff and replace refused entries with a safe no-source result before they are submitted as new source context; make request-stage cancellation checks explicit. Do not hold transactions through the model request. Persisted receipt state is described as **host-budget-admitted legacy byte history**. Predicted window coverage is explicitly prospective, not an acknowledged write or served model fact. Aggregate catalog coverage keeps its prior scope and is not promoted to current request/extraction proof.

Existing immutable receipt/audit history is retained. Do not retrofit text hashes into original `content_hash`, fabricate gateway IDs, provider acknowledgements or new accepted statuses. Exact extraction/current actor durability requires the separately specified V2 storage/host lifecycle increment.
