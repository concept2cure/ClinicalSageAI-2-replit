## What the controls establish

The actor scope follows current active membership and the canonical project-sharing policy. Active viewers, custom-role shares, private owners and pending artifact reviewers retain legitimate reads. Explicit malformed or contradictory project identifiers do not widen into organization-wide discovery. All organization anchors are considered before access intersection, so an accessible duplicate cannot launder a private anchor. Denied or unavailable policy state does not become an authenticated empty scope.

Real PostgreSQL cases put newer/high-ranked private files above the authorized source and verify actor filters before counts and page limits. Capture controls exclude another creator's unbound file, a private bound file and a program/workspace mismatch without exposing their names, failure reasons or counts. Eligible retained extraction discloses that the original is unavailable. Registered historical reads disclose current-use limits and earn no new current-source receipt. Optional query embedding cannot preserve stale lexical hits/counts after revocation. An unknown passage ledger stays unknown, and tenant integer/UUID mismatch refuses before passage retrieval.

Deferred receipts privately pin actor/source identity, the exact extraction digest, UTF-16 span and serialized payload. Same-length extraction replacement, changed source identity, withdrawn data, revoked access, mutated objects, invalid spans, budget replacement, cancellation and failed/zero-row insertion cannot mint a new qualifying receipt. Real database reservations fence selected source changes through the short receipt transaction. Actual host tests verify safe withdrawal when a source refusal is discovered after the first handoff guard, including a later refusal in a multi-read round: new Vault read strings are withdrawn, later INSERT attempts stop, and an already committed legacy count is reported without being rewritten.

## Practical limits

These checks concern **newly admitted source context** and the existing byte-bound receipt path. Replaying source text already present in prior conversation transcripts is a separate lifecycle boundary. Client/project memory, every other platform source reader, prior persisted receipts and deployed database permissions are not globally qualified here.

Current actor/extraction checks are transient. Existing receipt rows remain **host-budget-admitted legacy byte history**: they do not persist the extraction digest or prove current actor/turn coverage, provider acceptance or provider serving. An earlier committed receipt can remain when a later source refusal withdraws the round; its presence must not be represented as proof that the model received that source. Prospective coverage is conditional on host admission and a successful write. Durable extraction-specific/current-actor proof requires the separately specified V2 receipt and host-lifecycle increment.

Admission and post-await checks are bounded point-in-time guards. No transaction is held across model/provider work, and continuous remote-egress revocation is not claimed. Catalog/source table reservations can contend with ingestion or other tenants; production workload/performance qualification was not run. Passage coverage reports the recorded actor-scoped index ledger and does not establish extraction freshness, whole-document comprehension or scientific correctness. No accepted fact state, governed-write authority, validator qualification or agency acceptance is created by these reads.
