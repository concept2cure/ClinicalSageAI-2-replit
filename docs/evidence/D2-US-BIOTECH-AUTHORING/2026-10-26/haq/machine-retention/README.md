# Agency-response machine-origin retention

## What already exists

The first same-editor bridge read actual saved Authoring text/lineage and wrote actual live `machineAuthors` into the existing governed response action payload. `saveResponseTx` already stored every answer revision and its `agencyResponseDigest`. `recordGovernedAction` already paired an executed `c2c_ana_actions` row with `audit_logs`, including target, tenant, backlink and payload hash. Existing Authoring workflow governance already held positively machine-generated imported clauses without qualified generation evidence. The source adapter initially marked every response unknown and did not read those retained action receipts: explicit fresh import could therefore lose the known-machine hold. No replacement writer, store or editor was needed.

## Narrow corrective boundary

`agency-response-machine-origin.ts` reads only the currently admitted exact question's revision/action history, after the source adapter has checked current actor/project/letter visibility. Positive response revisions require complete contiguous history1..current, exact current text and one valid executed governed receipt per revision. Revision0 is only an empty answer with no history. Missing current/retained records, gaps, duplicate/malformed/moved receipts and wrong identity/digests fail closed409; histories over200 revisions or400 candidate actions refuse503 before unbounded processing.

The reader recomputes `agencyResponseDigest` from the immutable question identity/wording and each exact historical response. Action/audit tenant, target, command, domain/surface, backlink and payload hash must agree. The writer hashes `JSON.stringify`, while PostgreSQL JSONB reorders object keys, so the helper reconstructs this existing writer's exact bounded legacy/editor payload recipe and rejects unknown fields. It does not introduce a general ledger reader or change the global hash recipe. Audit IDs compare as text for the UUID runtime schema and the canonical harness's text audit IDs.

Actual `ana` comes from the canonical machine-author vocabulary. `workflow_import` is excluded: deterministic copying does not establish model origin. Current text retains a machine hold if its comparable full response equals an earlier known-machine revision (including short answers), or contains an existing known-machine clause of at least `MIN_MACHINE_CLAUSE_CHARS`. The canonical clause/comparison utilities preserve scientific numbers/operators. A later legacy responseText amendment retaining those words keeps their origin; complete removal can become unknown and never becomes a human-authorship assertion. Supporting receipt identities/revisions/digests/authors enter the source fingerprint. Context stays unknown; retained machine response text is marked machine with model/qualification unrecorded, so the existing governance hold applies to a fresh editor copy.
