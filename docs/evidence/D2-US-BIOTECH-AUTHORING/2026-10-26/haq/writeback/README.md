# Saved-editor response writeback fixture

## What already exists

`server/services/agency-responses/response-service.ts` owns the original letter/question/answer read model, current expected-revision check, sole `saveResponseTx` writer, response revision/history digests, independent content-bound approval standing and package prerequisites. `server/routes/c2c/agency-responses.ts` owns current recorded-project admission, visible-letter checks and governed writes. Canonical Authoring already owns source snapshots, object ACL admission, actual section PATCH writes, immutable CREATE receipts, saved clause lineage and source-current verification. The parent added a narrow saved-editor bridge to those existing systems; this test introduces no alternate response store or writer.

## Actual boundaries and fixture limits

This suite mounts the actual Authoring and agency response HTTP routers over isolated PGlite, verifies signed JWTs/current database membership and actual project admission, creates source copies using actual preview/import endpoints, edits via the actual canonical section PATCH endpoint, reads current saved hashes/times and exercises the parent-owned `editorSource` bridge to the existing SQL answer/revision writer. Actual GET editor-source and questions readback serve the UI contract. Actual response-package HTTP assembly refuses the changed, unapproved text.

The initial bridge epochs scripted `governedRequestWrite` sealing and the signing-authority check. That adapter ran the actual callback SQL inside BEGIN/COMMIT/ROLLBACK and captured its returned payload, without proving a real audit pair. The later machine-retention fixture now persists actual canonical action/audit pairs through `recordGovernedAction`; only seal computation and signing authority remain scripted. Details and newer qualifications are in `../machine-retention/README.md`. Prior/current independent-review signatures are seeded against actual response digests; these are explicit retained approval standing, not real signature ceremonies. No model, provider or agency submission occurs. The minimal agency fixture expands only the columns the real admission/read/write services use. Canonical migrations are listed literally in each test.
