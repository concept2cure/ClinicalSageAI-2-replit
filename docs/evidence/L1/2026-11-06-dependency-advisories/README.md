### zod — why it was fixed, not reviewed

Measured on zod 3.25.76 before the upgrade: a 2,000,001-byte JSON array (the `/api` body limit is 2 MB) of one million
`0`s, parsed against `z.array(z.string()).max(10)`, produced **1,000,001 issues and 276 MB of heap** in one
synchronous parse — zod 3's `ZodArray._parse` records the `too_big` issue and still parses every element
(`node_modules/zod/v3/types.js:1788-1806`). Request validation with zod sits in 244 server files, so the vulnerable
function is reached; a ledger row would have suppressed a reachable advisory.

No 3.x release carries the fix (3.25.76 is the last), so the upgrade is the fix. Using zod 4's bundled `zod/v3`
entry point instead was rejected: it is the same vulnerable code under a version number the scanner accepts.

Migration, all mechanical and positioned by the compiler (`tsc --noEmit -p tsconfig.json`: 362 errors → 0):

- `ZodError#errors` → `#issues` (80 sites placed by tsc, plus 9 in untyped `.js`/`any` code found by search:
  `server/api/ai/phase3-routes.js`, `server/api/semantic-search.js`, `server/routes/concept2cure.ts:1547`).
- single-argument `z.record(v)` → `z.record(z.string(), v)` (62 sites; zod 3's implicit key was string).
- `required_error` → `error: (issue) => issue.input === undefined ? msg : undefined` (same message on a missing
  field, zod's default otherwise — as before); `errorMap` → `error`; message-function second arguments of
  `.refine` → `{ error: ({ input }) => … }`.
- `z.ZodType<T, z.ZodTypeDef, unknown>` → `z.ZodType<T, unknown>`; `z.AnyZodObject` → `z.ZodObject`.
- `shared/csr-source-contract.ts`: the JSON-schema walker read zod 3 internals (`ZodEffects`, `_def.checks[].kind`).
  Rewritten over zod 4's check definitions. **Proof of equivalence:** the published contract generated by the
  unchanged zod 3 source (run against `zod/v3`) and by the rewritten walker on zod 4 are byte-identical
  (47,970 bytes, `diff` empty).

### @figma/code-connect — the ledger row

After the upgrade `npm ls zod --omit=dev --all` lists only `zod@4.6.7`. The single copy below 4.6.6 is
`node_modules/@figma/code-connect/node_modules/zod@3.25.58`. @figma/code-connect is a design-time CLI: no npm script,
workflow or Dockerfile stage runs it (`git grep -nE "figma connect|code-connect" -- .github scripts Dockerfile package.json`
finds only the package.json entry), the repository has no `*.figma.tsx` file, and `client/figma.config.json` carries
placeholder team/file ids. Its latest release (2.1.0) pins zod 3.25.76 exactly, so no parent release carries the fix,
and an override would force zod 4 onto code written for zod 3. The runtime image (`npm ci --omit=dev`) does not
contain it. Row `GHSA-mrhx-c7xc-m3w5`, owner Security Engineering, reviewed 2026-11-06, expires 2026-12-06; mirrored
as `CVE-2023-54404 exp:2026-12-06` in `.trivyignore`.

Gate note: the gate compares a row's `installedVersion` with the hoisted `node_modules/zod`, so the row records
`4.6.7` (fixed) and `dependencyType: direct`; the row's evidence names the nested 3.25.58 copy as the one reviewed.
