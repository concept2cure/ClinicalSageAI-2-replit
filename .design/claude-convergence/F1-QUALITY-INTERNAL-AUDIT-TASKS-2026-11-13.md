# Internal-audit tasks follow the current Quality record

F1, project/Quality/tasking completion. Baseline `55ce8003b` on `concept2cure-v2`, begun 2026-11-13.

## What already exists

- `server/routes/mdx-qms-records.ts` creates/patches the native organization-scoped internal-audit register. Its allowed statuses are planned, in_progress, closed and cancelled. Each native update and its audit recording precede the best-effort `scheduleInternalAuditTask` call. Legitimate concurrent PATCH requests can therefore deliver their task plans out of order.
- `server/services/qms/qms-record-tasks.ts` already owns the pure internal-audit task plan: a dated planned audit owes a start task, starting/closing completes it, cancellation or removal of its date withdraws it. It keeps the native key `qms-internal-audit:<id>` and existing source type `qms_internal_audit`. No new task type or scheduler is needed.
- `server/services/tasking/source-task.ts` owns one open task per native source and existing transactional/native reconciliation for CAPA, periodic review and training. Internal audits currently use the generic path, which reads no current audit row and uses no native transaction/lock. An older planned snapshot can create a pending start task after a newer in-progress snapshot completed the prior task. Older closure/date/owner plans can likewise overwrite newer work.
- The existing Quality transaction already serializes source work, writes through the same unified task store, audits changes in the transaction and refuses a lost status compare-and-set. Extend that path to this existing organization-scoped audit source. Keep its current project placement empty, and preserve the source-linked Quality task destination.
- Existing planner tests mock the task writer. Existing source-task SQL tests prove tenant/actor admission, stale CAPA plans and transactional rollback, providing the appropriate real-SQL harness pattern. No deleted replacement of the existing record/task owners was found in full history; checkout is not shallow.

The current coordination hold on `nativeTaskPlacement` and P-111 producer lines remains intact. Do not modify that function, training files, audit routes, source catalogue or Quality/TaskBoard UI. A separate periodic-review retirement race has additional release semantics and is not part of this slice. The sponsor-reassignment catalogue hypothesis has no current supported writer and is not treated as a reproduced user defect here.

## Bounded repair

Use the existing transactional reconciliation for `qms_internal_audit`. Verify an exact bounded native key, current organization actor and tenant-owned current audit under a row lock before reconciling tasks. Reuse the existing pure plan against current status/date/lead/content; reject stale desired/closure plans without changing the current task. Do not fabricate project placement. A rollback must preserve task and task-audit state on native/assignee/creation/status-CAS failures. The governed audit update remains committed and scheduling remains best effort.

Pre-edit keep-path review also found that the current pure planner's `same` predicate compares only its due metadata. The existing PATCH permits audit-number/scope edits without moving the date; a valid fresh plan can then leave the existing task's title/description stale. Extend the existing open-task projection with those existing columns. A text-only refresh must preserve task identity, progress and manual assignee rather than reset them through replacement; use a tenant/source/status/old-text compare-and-set inside the same transaction, with explicit text-change audit context. Date/lifecycle replacement behavior remains as before. Preserve generic/CAPA/training matching and manual assignment policy. Reject stale claimed lead values against the native row, but do not describe lead-reassignment tests as a supported PATCH feature (the PATCH does not expose that field). The old generic test using noncanonical `audit:12` is not an authority bypass to preserve; move that generic control to an actually generic existing source and add strict audit controls.

Before this final text-refresh edit, independent review identified a concrete issue in the initial close/replacement implementation: a valid same-date number/scope edit would cancel a manually assigned in-progress task and recreate it for the native lead. Add that negative control before repair and refresh the text in place. Audit the actual old/new text and explicitly unchanged status through the existing task transition record; do not manufacture a status move or person-stated reason. Compare against observed text as well as status to avoid losing a concurrent edit. Task/audit failure rolls the refresh back.

Add meaningful red-before-green SQL cases for delayed planned snapshots after start/close/cancel, stale closure/date/lead after replanning, valid scheduling/closure, denied/missing/foreign records, actor refusal and rollback/CAS loss. Run adjacent CAPA/training/periodic/general task regressions, scoped lint, full compiler and normal publication gates. No model/provider call, new API mount/table/service/subsystem/dependency or approval change.
