### WA.3 Claude's pattern

claude.ai's own list pages (Projects, a project's knowledge, Settings) are one calm column: a serif title, one grey
line, one action at the right, then the thing itself as a list or a grid. Nothing above the title. Help is the
conversation. A Concept2Cure work area is that page with its domain's views under it:

```
┌ .page-inner[data-work-area] max 1120, padding 32/40/96 (D0) ─────────────────────────────────────────┐
│ ← [Demo · Biotech] C2C-101 anti-IL-23p19 mAb — plaque psoriasis (IND)        .pj-back, 13px, 12px gap │
│ CMC / Module 3                                            [Ghost secondary]  [Primary]  .ph / .ph-acts│
│ Module 3 for this IND, and the quality records kept while the study runs.      .ph-sub 14px text-300  │
│                                                                                                       │
│ (✻ Run the ICH compliance check…) (✻ Generate the control strategy) (✻ What blocks my shelf life?)    │
│                                                         .sp-starters[data-layout=row], ≤3, 24px below │
│ [Records | Module 3]                                                 .seg, only where a page has modes│
│ Overview   Quality by design   Module 3 build   Approvals & audit                    .tabs, one row   │
│ ───────────────────────────────────────────────────────────────────────────────────────────────────── │
│ Section approvals                                    21 sections · 18 approved     [+ Add] ghost small│
│ §          Path                         Completeness   State                                          │
│ 3.2.S.1    General information          100%           Approved                                       │
│ …                                                                     .pj-sec (typographic) + .reg-tbl│
│                                                                                                       │
│ Portfolio                                             1 submission                       32px between │
│ …                                                                                                     │
│ ▸ How this is measured                                                         .pj-more, closed       │
└───────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

- **Grid.** `.page-inner` (D0): `max-width: 1120px`, padding `32px 40px 96px`; `24px 24px 80px` at ≤1023;
  `20px 16px 72px` at ≤640. One column. A work area that is a list with a detail (Vault, Tasks' drawer) opens the
  detail as the D0 drawer; a work area that is permanently two-pane (Vault's library, RBM with its AnA dock) docks
  `.de[data-docked]` at 360px beside a `minmax(0,1fr)` column, collapsing to the drawer at ≤1023.
- **Type.** Back link 13px `--text-300`. Title `.ph-title`: Lora 26/1.25 weight 500 (22 at ≤640), the rail label
  verbatim. Description `.ph-sub`: 14/1.5 `--text-300`, 68ch, **one sentence**. Starters 13px `--text-200`. Tabs 14px
  weight 500. Section heading 15px weight 600 (`.pj-sec-h h2`), its count 13px `--text-300`. Table header 12px, cells
  13px. Nothing below 12px. No uppercase.
- **Rhythm.** Back link → title 12px; title → description 6px; header → starters 16px; starters → mode/tabs 24px;
  tabs → first section 24px; section → section 32px; heading → body 12px.
- **Actions.** At most **one** `btn primary` per view. It is rightmost in `.ph-acts` when it is the work area's own
  act whatever the view (New task, Log communication, Add files, New controlled document). In a tabbed area whose main
  act differs per tab (CMC, Submission Center), the header holds no primary and the active tab's lead row
  (`.pj-sec-h` → `.pj-sec-acts`) holds it as `btn primary small`, so the position is the same on every tab. Secondary
  actions are `btn ghost`, at most two in the header; the rest live in their section's `.pj-sec-acts` as
  `btn ghost small`, or in a row's own actions. AnA's entry is the starter row, not an orange "Ask AnA" button.
- **Colour.** Orange only for the one primary, the starters' ✻ glyph and focus. Status colour (`--success`,
  `--warning`, `--error`) only for a status word or chip that means it, always with the word.
- **Motion.** 200ms ease-out on hover fills, the tab underline and the drawer; no transforms.

#### WA.4.2 The markup contract (each owner applies it to its root render)

1. **Root.** The work area's outermost element keeps its existing container class and test hooks and gains
   `data-work-area="<surface id>"`. Its container becomes `.page-inner` (or `.sp` where the surface is its own scroll
   box), so the D0 width and gutters apply. Inline `style={{ maxWidth: … }}`, `style={{ padding: … }}` wrappers around
   page children are deleted.
2. **Back to the project** — only where the area is project-scoped and a project is open (`useShellProject()` non-null):
   ```tsx
   <button type="button" className="pj-back" onClick={() => onNav?.('project-home')}>
     {I.left} {project.title ?? 'Project'}
   </button>
   ```
   It replaces "Open project" buttons, the RBM "Project management" link card, and CMC's "Project" destination chip.
3. **Header.**
   ```tsx
   <header className="ph">
     <div>
       <h1 className="ph-title">{getSurfaceMeta('<id>').label}</h1>
       <p className="ph-sub">{oneSentence}</p>
     </div>
     <div className="ph-acts">{/* ≤2 btn ghost, then ≤1 btn primary */}</div>
   </header>
   ```
   No eyebrow. A dynamic context that used the eyebrow (a project name) is the back link; a dynamic fact
   ("2 letters need a response") goes in `ph-sub`.
4. **Ask AnA.** The answer banner, the "What to do now / Next step" box, "Where to start" and the orange "Ask AnA"
   buttons are replaced by one row, after the header:
   ```tsx
   <div className="sp-starters" data-layout="row" aria-label="Ask AnA">
     {starters.slice(0, 3).map((s) => (
       <button key={s.label} type="button" className="sp-starter" onClick={() => onAsk(s.prompt)}>
         <span className="sk" aria-hidden="true">{I.sparkles}</span><span>{s.label}</span>
       </button>
     ))}
   </div>
   ```

   - its `eyebrow` (the question: "What is the FDA waiting on from you") → the **first starter**, label = the
     question in sentence case, prompt = the question;
   - its `headline` (the answer) → `ph-sub` when it is a fact the page is for ("2 letters need a response, the soonest
     due in 3 days"), else the AnA surface context (`usePublishSurfaceContext` `summary`), which already carries it on
     every screen that has the lead;
   - its `body` → the AnA surface context (already published on CMC, Tasks, Communication, Submission Center,
     Biostatistics);
   - its `action` → the header's one `btn primary` when it is the page's main act, else a `btn ghost` in
     `.ph-acts`; its `alt` → a `btn ghost` in `.ph-acts` or the section it acts on;
   - its `reassure` and `secondary` ("Or work … below") → deleted: the first is AnA's voice and belongs in her
     reply, the second describes the page to itself.
   The one place an answer *is* the screen — Submission Readiness's dispatch verdict, inside Dispatch — keeps
   `AnswerLead emphasis="verdict"` (D7 §A).
5. **Modes and views.** A page with two halves uses `.seg` (`role="group"`, items `aria-pressed`). Views use `.tabs`
   with `role="tablist"` and `role="tab"` / `aria-selected`; labels without icons; one row that scrolls. Never a tab
